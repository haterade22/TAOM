## 3. The proposed fix, and what to do instead

**Lens fix (b).** A finalizer on `Mission.OnTick` and another on `Mission.TickAgentsAndTeamsImp` set `tickCompleted = true`
through `AccessTools.FieldRefAccess<Mission,bool>("tickCompleted")`, then "let the exception continue to Patch37". It touches
one private instance bool by name (Mission.cs:1040) and two public methods. The write is a plain store, like the engine's own.

**What goes wrong as written.**
1. **Throw after the async launch.** Harmony runs prefixes, the body and postfixes inside one `try`, so a finalizer also sees
   a postfix's exception. `Patch35_Mission_OnTick` (a postfix for every player, applied at SubModule.cs:1575) and any foreign
   postfix run after 3770. If one of them throws after the job has launched, the flag is false only because the job is still
   running. Setting it true lets the next `OnPreTick` pass while agent tick N runs. `OnTick` N+1 then clears the flag at 3740,
   and job N sets it true at 3613 during N+1's behaviour loop. From then on every `WaitTickCompletion` passes while the
   previous job is still running: the handshake stays off by one, and behaviour ticks overlap agent ticks (the race class
   behind #592 and #634). 1.5.x wrote this case down (1.5.x `docs/features/mission-perf-heartbeat.md:415-420`).
2. **Agent-tick path.** On the job thread there is no Patch37 above `TickAgentsAndTeamsImp`; the next catcher is the
   Native2Managed shim. A restore there releases the main thread while the shim runs a full, untagged capture on the job
   thread: Mission and Campaign collectors, then `CrashNotifier.Notify` calls `InformationManager.ShowInquiry`
   (CrashReportService.cs:121, 138-146; only `AppDomainExceptionHook` sets the tag). That is worse than today, because the
   main thread is now live.
3. **PatchShield order.** A recovery finalizer that runs after PatchShield's sees no exception once PatchShield has
   swallowed it, so the recovery must run at `Priority.First`.
4. **New PatchShield target.** On 1.4.x, any patch on `TickAgentsAndTeamsImp` makes PatchShield wrap it from the next pass,
   because 1.4.x has no per-method exclusion. A missing-API swallow there exits before 3613. This also applies to porting
   f75288ebf's Patch91 (`Patch91_MissionTickStallProbes.cs:15-24` at f75288ebf), which 1.5.x protected with 6eb2e1b90's
   exclusion of `TickAgentsAndTeamsImp` and `WaitTickCompletion`.

No variant runs an extra agent tick, so double ticks are not the risk. The risk is overlap (item 1).

**Alternative R: rethrow instead of swallow.** It needs coordinated changes to three swallowers (Patch37 on
`Module.OnApplicationTick`, Patch37 on `Managed.ApplicationTick`, the Native2Managed shim), plus stack-based detection. The
outcome is whatever native does with an escaped exception (UNVERIFIED, probably a crash to desktop). It also breaks the
documented always-swallow contract. 1.5.x reverted rethrows on this path in bd1ac8292 because the next catcher swallowed and
hung instead. Use it only if the maintainer prefers a crash to recovery.

**Alternative T: MissionStartGuard design on `Mission.OnTick`.** Swap the single `MissionBehavior.OnMissionTick` call
(Mission.cs:3743) for a try/filter helper. It gives the best outcome for the commonest source: one broken behaviour misses
its tick while the rest of the frame and the agent tick go on, with no private field. Its gaps: lines 3745-3767 and the
inline agent tick stay uncovered, it needs a call-site swap helper that 1.4.x lacks (1.5.x `TickProfilerTranspiler` from
6eb2e1b90), and a throw that recurs every frame needs throttled logging plus its own report path, because Patch37 no longer
sees it.

**Recommended design: completion-aware tick recovery on `Mission.OnTick`.** 1.5.x wrote this remedy down but never built it
(no 1.5.x code writes `tickCompleted`). Bind these members:
- `TaleWorlds.MountAndBlade.Mission.OnTick(float, float, bool, bool)` (public, Mission.cs:3636): a prefix at
  `Priority.First` that sets `__state = true` and opens a launch token for this call; a **void** finalizer at `Priority.First`.
- `TaleWorlds.MountAndBlade.Mission.TickAgentsAndTeamsAsync(float)` (public, Mission.cs:1825): a prefix that marks the token launched.
- `TaleWorlds.MountAndBlade.Mission.tickCompleted` (private instance bool, Mission.cs:1040): read and written through a
  cached `AccessTools.FieldRefAccess<Mission, bool>("tickCompleted")`, behind an adapter (ADR-007).

**Rule.** When `__exception != null`, the prefix ran, the token is not launched and the field reads false: write true and log
one throttled ERROR. The finalizer returns void, so the exception keeps its stack and Patch37 still reports it.

**Why it is safe.** A false flag with no launch in this call means this call cleared it at 3740 and no job is in flight; the
previous job finished before this frame's `OnPreTick` returned. That ordering is the engine's own invariant, read from native
behaviour by inference. The rule covers behaviour throws, lines 3745-3767 and an inline agent tick that throws before 3613. It
does nothing for a throw before 3740 (the flag is true) or after a launch (the token is set).

**Outcome.** One skipped agent tick plus a crash report. If the throw recurs every frame, the main thread still runs and menus
work; that is degraded play, not a hard freeze.

**Route 2 is a separate maintainer decision.** To keep it recoverable, add a void `Priority.First` finalizer on
`Mission.TickAgentsAndTeamsImp(float, bool)` (Mission.cs:3601) that restores the flag, but only after the off-main-thread
capture verdict is ported (8c84fa20e on 1.5.x), so the shim's capture on the job thread skips collectors and UI. The other
choice is plan 006's allowlist: 1.5.x `Native2ManagedTargets.cs:28-61` has 16 entries and no `Mission_TickAgentsAndTeams` or
`Mission_OnPreTick`, which hands the exception to native (UNVERIFIED).

**For the `AfterStart` loop, port MissionStartGuard.** Changing SaveShield alone cannot help: a rethrow there lands on Patch37,
which also swallows, and the loop goes on. Port MissionStartGuard from its only 1.5.x commit, ecaa67d26 (no later commit touches
`Main/Features/MissionStartGuard`). Its transpiler swaps the six calls (Mission.cs:3807, 3811, 3815, 3819, 3825, 3829; the C#
body shows one each, and the ported `MissionStartGuardBindingTests` must pin the IL count). It adds a prefix and an
observe-only void finalizer at `Priority.First`. Take ecaa67d26's SubModule hunk as well: it registers `BattleLoadPhaseBehavior`
in a `finally` with a `GetMissionBehavior<>` duplicate check. The port needs a call-site swap helper and 1.4.x wiring in IoC.cs
and SubModule.cs instead of `Main/Composition`. Take the AfterStart dev trigger from 649cc30ff, that hunk only.

## 5. Corrections to the lenses

1. **LOADING-HANG-03.** The swallower is SaveShield on `MissionState.FinishMissionLoading`, not the Native2Managed finalizer
   on `Managed_ApplicationTick`. The predicted per-frame `[CrashReport] ... bundle suppressed` line does not happen. The log
   shows repeating BattleLoad phases, plus diag.log lines.
2. **FREEZE-THREADING-04.** The throw never "unwinds out of `MissionState.OnTick` to Patch37". SaveShield swallows it one

   it first.

   from the second game start. "Always writes a `[CrashReport]` block" holds for E3 and E4 only.

   agent-tick path, the exception goes to the Native2Managed shim, not to Patch37.
5. **Both lenses.** "Reloads every frame" is approximate: a pass ends when native reports `IsLoadingFinished`. Each pass also
   re-adds every submodule's behaviours to the same `Mission`.
