# TAOM Tools

Data generation, rebalancing, and content pipeline scripts.

All Python scripts support `--dry-run` (preview) and `--apply` (write). Run from the repo root.

## XML I/O convention (MANDATORY for scripts that edit ModuleData XML)

Bannerlord ModuleData XML is UTF-8 (some files with a BOM, e.g. `TAOM_Map/settlements.xml`; most repo files without) and CRLF. To edit byte-faithfully:

```python
had_bom = path.read_bytes().startswith(b"\xef\xbb\xbf")   # detect
text = path.read_bytes().decode("utf-8-sig")            # decode (strips the BOM, keeps CRLF; read_text would translate it to LF)
# ... regex edits ...
path.write_bytes((b"\xef\xbb\xbf" if had_bom else b"") + text.encode("utf-8"))   # write, re-prepend BOM as bytes
```

- **Never** write the BOM as a string literal `"﻿"` (fragile if the `.py` is re-encoded).
- **Never** read with plain `utf-8` (leaves the BOM as a stray U+FEFF in the decoded string).
- **Sanctioned alternative** (used by `Assign-SettlementOwners.py` + `rebalance_settlement_prosperity.py`): the full byte round-trip — `raw = open(path,'rb').read()`, `text = raw.decode('utf-8')` (BOM survives as a leading U+FEFF *character*), regex edits, `open(path,'wb').write(text.encode('utf-8'))` (re-emits the BOM bytes). Equally byte-faithful because both read and write are binary-mode (no CRLF translation) and the BOM travels inside the string; the "never plain utf-8" rule above targets the mixed pattern (`utf-8` decode + `write_text`), not this symmetric one. Pick either idiom; don't mix them in one script.
- **Line endings are not uniform across ModuleData either. Capture the terminator and re-emit it verbatim instead of assuming one.** `taom_partyTemplates.xml` has a BOM and plain CRLF. The `Main/_Module/ModuleData/Languages/**` XML files have **no BOM** (0 of 277, measured 2026-10-21), and their terminators vary by file type and by line: doubled CR (`\r\r\n`), plain, or both in one file. Measure the file in front of you and re-emit each line's own terminator; the per-type table is in [TRANSLATOR_GUIDE](../docs/localization/TRANSLATOR_GUIDE.md) "Line endings and encoding". Both halves bite: a pattern that puts `\r?\n` straight after the matched text finds nothing on a doubled-CR file (the spare `\r` sits between them), and "normalising" the endings rewrites every line, which is exactly the whole-file diff this convention exists to prevent. Match with `(\r*\n)` and write the captured group back.
- **Second sanctioned alternative** (used by the four `*_black_numenorean_*` scripts): symmetric **text** mode with newline translation switched off on both sides: `open(p,'r',encoding='utf-8',newline='')` for the read and `open(p,'w',encoding='utf-8',newline='')` for the write. Byte-faithful for the same reason the binary round-trip is: a BOM decodes to a leading U+FEFF *character* and Python's `utf-8` codec re-emits it as `EF BB BF`, while `newline=''` suppresses translation in **both** directions so CRLF, LF and doubled-CR all survive. Verified against `taom_partyTemplates.xml`, the one BOM'd target, 2026-08-17. The "never plain `utf-8`" bullet above targets the **asymmetric** shape (plain-`utf-8` read plus a default-newline write), where the write-side CRLF normalisation is what does the damage. It does not forbid this one. As with the others: pick an idiom and don't mix them in one script.
- **Text you insert must carry the file's endings too, and pick them by majority, not presence.** A writer that round-trips faithfully still corrupts the file if the block it appends is hardcoded `\n`. And `"\r\n" if text.count("\r\n") else "\n"` is the wrong test: `LOTRLOME_items/mordor/*_armors.xml` are genuinely mixed (2356 CRLF against 517 bare LF in `head_armors.xml`), so use `crlf > total_lf - crlf`.
- Back up before destructive writes: `path.with_suffix(path.suffix + ".bak").write_bytes(path.read_bytes())`. Guard it with `if not os.path.exists(bak)` when the backup name is date-stamped, or a partial same-day re-run replaces the pristine copy with already-modified content. `.gitignore` covers `*.bak*`, so dated sidecars (`.bak-blacknum-20260817`) are ignored as well as bare `.bak`.
- **The backup suffix must come LAST, after the real extension.** `foo.xml.bak-topic` is correct; `foo.bak.xml` is a bug, because the engine globs `GetFiles("*.xml")` in registered folders and will parse it as real data, duplicating every id in the file. This is why the Armory change docs call the non-`.xml` extension load-bearing.
- **Sidecars written into a live module folder do not clean themselves up, and they must not ship** (`.bak` breaks the Cloudflare distribution). `pwsh tools/sweep_module_backups.ps1` sweeps all three modules into a dated quarantine with a SHA256 manifest; `/release` Phase 2 gates on it reporting zero. A tool with a `--revert` flag depends on its backup sitting beside the live file, so after a sweep, restore from the quarantine before reverting. See [`docs/reference/module-backup-sweep.md`](../docs/reference/module-backup-sweep.md).
- Scene/asset/id comparisons must be **case-insensitive** (Windows lookup is) — lowercase both sides.
- **A generator that owns a `<!-- MARKER:BEGIN/END -->` region writes it through `_marker_region.replace_region`**: in place, never deleted and re-appended at the closing tag (that reads as drift once another block follows it, #947), and refused when the file holds two regions, a lone marker or no closing tag (#975). Tests: `tools/tests/test_marker_region.py`.
- **A script that writes several files parses every output before it writes any**, in every mode. Writing a file and then parsing it leaves the broken file on disk and the rest unwritten (#979, `promote_borrowed_cultures.py` `unparsable`).

Reference: `docs/reviews/rca-scene-tooling-2026-05-28.md` (why this convention exists) + `.claude/rules/vanilla-data-comparison.md`.

**Mandatory before trusting any of the writers.** A tpac header's 8 bytes at offset 28..35 are the
TOC size, and the engine derives `data_start = 36 + toc_size` from them. A writer that zeroes that
field makes the engine read the table of contents as vertex data, which surfaces as
`rglBuffer.cpp:899  nearly_equals(vector->w, 1.0f)` during asset load and nothing more helpful. That
defect shipped in `tpac_skeleton_inject.py` and cost two failed attempts before it was found
(fixed 2026-08-31). So: parse the file, re-serialise it with no modifications, and confirm the
result is byte-identical to the original before letting the tool near real data.

**Never save a MESH or MATERIAL package through upstream TpacTool.Lib.** Per the MithrilForge project
(`docs/reviews/adopt-yotthani-animation-handoff-2026-09-18.md`), upstream `Save` writes a +56-byte prefix per vertex
channel (a native AV in the GPU morph pass), sets the 32-bit index flag from the index count where the reader
uses the vertex count (silent corruption above about 21,845 faces), and cannot write Material metadata at all;
their private fork patches all three. TAOM writes meshes with `tpac_clone_metamesh.py` and uses TpacTool `Save`
only on clip and master packages (`wire_anim_master_clip.ps1`), which none of the three touch. Not re-measured
by TAOM.

**Which TpacTool the PowerShell tools load** (since 2026-10-14): ShortJake's TpacTool v0.5.1 from
`E:\Release_v0.5.1\bin`, the `-TpacBin` / `-TpacToolBin` default of every `.ps1` here. Its library changes from
0.4.0 the tools account for: `AnimationClip.BlendWithAnimation` (was `UnknownClipName`), `Vector4`
`ClipUsage.DisplacementVector` and skeleton body positions, and `AssetPackage.Save(path, useOriginalChecksum,
version)`, so a write is `Save($out, $false, 2)`. The fork's only mesh-writer change is `Mesh.Write` round-tripping
`SubVersion`; none of the three defects above is touched, so the warning stands. Unblock the folder after a fresh download, or Windows PowerShell 5.1 refuses the DLLs (`0x80131515`):
[development-machines.md](../docs/reference/development-machines.md). One tool does not run under v0.5.1 yet:
`extract_human_anims_tpac.ps1` (the old Auto-Rig Pro route) stalled at "loading animations.tpac (resolver)" on
2026-10-14, cause unknown; `read_anim_keyframes_tpac.ps1` replaced it for human clips.

**`tpac_clone_metamesh.serialize` writes packed, like the Kit and every vanilla package; MithrilForge prop
packages are 8-byte aligned** (2026-09-29). The parser reads the four `Main/_Module/AssetPackages/*.tpac`
correctly, but re-serialising one is not byte-identical (16 to 25 bytes short). `parse` and `serialize` need
neither `lz4` nor `xxhash`. Gate: `tools/tests/test_prefab_asset_packages.py` (the prefab meshes the code passes

**Configuration:**
- Overrides (hand-curated canonical translations, e.g. Tolkien proper nouns): `tools/translation_overrides/<lang>.json` — git-tracked, edit freely
- Cache (machine-written API results): `tools/translation_cache/<lang>.json` — git-tracked, ~700KB-1.3MB per language

**Setup:** Set `ANTHROPIC_API_KEY` env var. Estimated cost ~$3-10 per language for a full first pass (~15,000 strings). Cache makes re-runs effectively free.

**Usage:**
```bash
# Preview what would be translated and rough cost (no API calls):
python tools/translate_with_claude.py --lang RU --dry-run

# Pilot a small batch first to validate prompt quality:
python tools/translate_with_claude.py --lang RU --module TAOM --max-entries 50 --apply

# Full run for a language (all 45 files across 3 modules):
python tools/translate_with_claude.py --lang RU --apply

# Translate just one module:
python tools/translate_with_claude.py --lang RU --module Armory --apply

# After API runs: rebuild XML files from cache + overrides
python tools/rebuild_translation_files.py --lang RU
python tools/rebuild_translation_files.py --all  # all 12 langs

# Status check on a running parallel batch:
bash tools/translation_status.sh
```

**Parallel runs:** `translate_with_claude.py` can be safely run for multiple languages in parallel (each language uses its own cache file — no contention). Recommended for full-suite refresh.

**Quality enforcement:** the script validates that every `{VARIABLE}` and `{?GENDER}{?}{\?}` placeholder/conditional, and conversation animation tags (`[ib:closed]`, `[if:convo_angry]`, `[rb:...]`, `[rf:...]`, counted per exact tag), present in the English source is preserved verbatim in the translation. Translations that fail validation keep the English text, so a row never gets broken markup.

**Idempotent / resumable:** cache persists every batch, so an interrupted run resumes from where it stopped on the next invocation. Re-running a fully-translated language is a no-op.

See `docs/localization/TRANSLATOR_GUIDE.md` for the translator-facing workflow + canonical Tolkien name conventions per language.

**Resolve it through `tools/_gamedir.py`** — 22 of the 25 do. `game_dir(default)` treats a set-but-blank
variable as unset, which `os.environ.get(VAR, default)` does not: it returns `""`, `Path("")` is `.`, and
the tool then reports every file missing rather than the root being wrong. `game_modules(default)` adds
the `BANNERLORD_GAME_MODULES` precedence, and `ensure_exists(path, what=...)` exits 2 naming the path,
for the tools that would otherwise end on a clean-looking result against a root that is not there.

here from `skeleton_hit_capsules.py`, 2026-09-23, so `apply_animalia_armory.py` uses the same one).
`dump_settlement_buildings.py`, `rebalance_armor.py` and `rebalance_settlement_prosperity.py` keep their
own inline resolution: they already handle the blank case, and two of them define a local `game_dir()`
that the import would shadow.

`taom_mcp_server.py` derives its Modules folder from `BANNERLORD_GAME_DIR`, keeping

and `TAOM_MAP_FILE` (`merge_settlements.py`). `tools/.env.example` documents all four.
