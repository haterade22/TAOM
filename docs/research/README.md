# docs/research/ — compiled wiki nodes

This directory holds **LLM-compiled summaries** of source material from [docs/raw/](../raw/). Each `<topic>.md` file in this directory is a wiki node: summary + source citations + cross-references to existing feature docs and memory entries + open questions for the next compile pass.

See [ADR-010](../adrs/010-knowledge-base-architecture.md) for the knowledge-base architecture this layer participates in.

## What lives here

- **One file per topic** matching the subdirectory layout under `docs/raw/`. If `docs/raw/tolkien/middle-earth-geography/` has source material, then `docs/research/middle-earth-geography.md` is the compiled wiki node.
- **Bot-authored.** These files are generated by the `/knowledge-compile` skill. Hand-editing is discouraged — re-run the compile instead, and update `docs/raw/<topic>/` to change what gets summarized. *Exception*: edit the **Open questions** section by hand to refine what the next compile should focus on.
- **Cross-referenced into the curated wiki.** Each research node links to relevant `docs/features/*.md`, ADRs, memory entries (by filename), and any other research nodes. Auto-generated `## Referenced by` footers (by `tools/build_backlinks.py`) will wire the inverse direction once `/build-backlinks` runs.

## What does NOT live here

- Canonical feature documentation — that's `docs/features/`.
- Architectural decisions — that's `docs/adrs/`.
- Adversarial-review outputs — that's `docs/reviews/`.
- Raw source material — that's `docs/raw/`.

A research node is the **compiled output of summarization, not authoritative knowledge**. When a research node's content becomes load-bearing for code — e.g., a Tolkien-lore distillation that drives culture-feat authoring — promote the relevant excerpts into the appropriate feature doc or ai-includes guide. Research nodes are scratch space for "I learned X about topic Y from these sources"; the canonical home for that knowledge is the curated wiki layer.

## Conventions for research-node structure

Every node should have these sections (the `/knowledge-compile` skill enforces this; see `.claude/skills/knowledge-compile/SKILL.md`):

```markdown
# <Topic>

> Source materials: `docs/raw/<path>/` — N files, last compiled YYYY-MM-DD

## Summary

One or two paragraphs that capture what the raw material collectively says.

## Sources

- `docs/raw/<path>/file1.md` — one-line per-file description
- `docs/raw/<path>/file2.md` — ...

## Cross-references

Existing TAOM knowledge that connects to this topic:

- [features/<name>.md](../features/<name>.md) — how this topic relates
- [reviews/rca-<name>-<date>.md](../reviews/rca-<name>-<date>.md) — past lesson learned
- Memory: `feedback_<name>` — relevant captured guidance

## Key claims

The non-obvious propositions extracted from the source material, framed so a future session can quote and verify them. Each claim should cite the file in `docs/raw/<topic>/` it came from.

## Open questions

Gaps in the raw material, contradictions between sources, or follow-up research that would improve this node. The next compile pass should address these (or the user should add new material to `docs/raw/<topic>/`).
```

## How to add a topic

1. Create `docs/raw/<topic>/` and drop source material into it (markdown, with attribution).
2. Run `/knowledge-compile <topic>`.
3. Review the generated `docs/research/<topic>.md`.
4. Optional: edit the **Open questions** section to focus the next compile.
5. Re-run `/knowledge-compile <topic>` whenever new material arrives.
