## Issues flagged

1. CLAUDE.md is 503 lines (>300) — could move repeating rules into scoped `.claude/rules/`. Estimated savings: ~2,640 tokens.
2. Heavy rule: `csharp-architecture` (104 lines, slightly over the 100-line flag).
3. MCP tool count is ~68 across 5 servers — schemas dominate context.

## Decision: defer two-layer skill injection and compression picks

The adoption plan included a decision gate (Phase 1 → Phase 2 promotion) for two picks:

- **Pick #2 — Two-layer skill injection** (load skill names in base context, bodies on demand)
- **Pick #3 — Three-layer context compression** (micro_compact + auto_compact)

Both are **deferred** based on this baseline. With 95% headroom on a 1M context window, neither addresses a real constraint. Re-evaluate if:

- We move to a smaller-context model (Sonnet 200K, Haiku) where 60K becomes 30%
- Skills count grows past ~30 or MCP tool count past ~120
- We start hitting auto-compact mid-task during routine work

## What's NOT counted

- User message history (variable per session)
- Claude Code system prompt boilerplate (fixed, ~3-5K tokens)
- Memory file contents (loaded on demand)
- Plan files
- Tool call results during a session
