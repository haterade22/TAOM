# Armoury mesh catalogue

`catalogue.tsv` beside this file is a generated, committed inventory of every mesh and collision
body `LOTRLOME_Armory` ships. It exists so that when an artist reorganises the module you can
**diff the catalogue** instead of discovering the damage from in-game symptoms.

Generated by [`tools/generate_armory_catalogue.py`](../../../tools/generate_armory_catalogue.py).
Do not hand-edit the TSV.

## Why it exists

On 2026-09-01 a 7-commit cleanup landed in `lotraom-assets` and synced into the live install. The
sync was clean, but the reorganisation deleted art that XML still named and item definitions that
troops still equipped: **275 validator errors**, found from blank icons in a screenshot rather than
from any diff. There was nothing to diff against, because every hand-maintained list had already
rotted:

- `tools/dale_armor_meshes.txt`, 169 names, written once in May and never touched
- the `armory-guide.md` Gondor row, which carried 5 of 17 regional tokens for months
- `tools/reports/mesh-audit/`, 252 names out of date, and gitignored so it could never diff

This is the missing baseline.

## What it is not

Not a validator. [`validate_mesh_refs.py`](../../features/mesh-ref-validation.md) answers "does
every referenced mesh exist". This answers "what exists, and where did it come from". The
`referenced` column is what joins the two.

## Commands

```bash
python tools/generate_armory_catalogue.py                 # regenerate after an art drop
python tools/generate_armory_catalogue.py --check         # drift gate, exits 1
python tools/generate_armory_catalogue.py --diff          # rename-aware change report
python tools/generate_armory_catalogue.py --compare-repo E:\repos\lotraom-assets\v1.4\LOTRLOME_Armory
```

## Reading a change report

`--diff` classifies every change rather than printing a raw line diff, because the four cases need
different responses:

| Class | How it is detected | What to do |
|---|---|---|
| **RENAME** | a name disappears and a similar one appears **in the same tpac** | re-point the items naming the old id. If the old name was `referenced=Y` this is an underwear bug on the next restart |
| **MOVE** | same name, different tpac path | nothing. Item XML is unaffected. This is the class that made the 2026-09-01 cleanup look far worse than it was |
| **DELETE** | gone, and no added name in its tpac or basename resembles it | if `referenced=Y`, hand to `audit_deleted_mesh_impact.py` for the roster blast radius. If `N`, it is free |
| **NEW** | added, matching no removal | nothing |

**Rename detection deliberately does not use git.** `*.tpac` is LFS-tracked, so git compares
~130-byte pointer files whose text is near-identical boilerplate. Measured against the 2026-09-01
commits, `-M --find-renames=40%` fabricated 37 renames between wholly unrelated cultures (a Dol
Guldur texture "renamed" to an Arnor steelbow). The `tpac` column is the join key instead, with a
basename fallback and a similarity check inside the candidate set.

## Columns

`mesh, kind, prefix, culture, sub, category, tier, variant, folder, tpac, referenced, source`

Two things about the format are load-bearing:

- **It is TSV, not markdown.** One shipped mesh carries eight embedded NUL bytes
  (`sk_dwarf\x00\x00\x00\x00\x00\x00\x00\x00_10`) and four contain spaces. A markdown table cannot
  represent those, and any whitespace-delimited dump splits them into phantom extra rows, which is
  exactly what the retired `mesh-audit` text dump did. Values are C-escaped.
- **Both `folder` and the name-derived columns are kept.** Neither is sufficient: the name carries
  sub-region and tier that the folder does not (`gondor_assets/` holds all 17 Gondor regions),
  and the folder carries the only culture signal for the names with no convention prefix. When the
  two disagree, that disagreement is itself the interesting signal.

## What keeps it honest

The failure mode for a file like this is silent staleness, so:

1. **`--check`** regenerates from **your live install** and exits 1 unless it reproduces the
   committed TSV byte-for-byte. It is an *install-versus-snapshot* comparison, not a repo
   self-check: a different machine, a newer art drop, or an edit to the live Armory's item XML
   all fail it legitimately, and with no game installed it exits 2. So do **not** put it in CI,
   which has no install. Run it after an art sync, on the machine that did the sync. The
   precedent for this shape is `.claude/hooks/check-polearm-shield-parity.sh`, which exists for
   the same reason.
2. **The unclassified gate.** If a mesh resolves to `culture=unknown` or `category=unknown` and has
   no row in [`tools/armory_catalogue_overrides.tsv`](../../../tools/armory_catalogue_overrides.tsv),
   the generator exits 1. A new naming shape fails loudly instead of quietly widening an `unknown`
   bucket. That override file is hand-maintained but **bounded and genuinely small**: 802 on the first
   run, 206 after the vocabulary was extracted from the live names, and **3** once the parser
   learned to split on whitespace, strip trailing indexes and read Rohan's abbreviations. An
   override that records `unknown` is REJECTED with a warning, because a row that repeats the
   parser's failure satisfies the gate while deciding nothing.
3. **It is not under `tools/reports/`.** That directory is gitignored, which is the single
   mechanical reason the previous mesh inventory rotted invisibly for six weeks.

## Source of truth

Generated from the **live install**, because that is what the engine loads. Confirmed in an
`rgl_log`:

```
Loading packages $BASE/Modules/LOTRLOME_Armory/Assets...
```

TAOM and TAOM_Map ship both a cooked `AssetPackages/` and a loose `Assets/` tree, and the engine
names `Assets` for each, so loose wins outright. `--compare-repo` reports the delta against the
versioned copy in `lotraom-assets`.

`EmAssetPackages/` is never a source. The generator globs `<module>/Assets/**/*.tpac` directly, so
both `AssetPackages/` and `EmAssetPackages/` are out of scope by construction. This module has no
`EmAssetPackages` at all.
