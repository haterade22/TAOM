## Bottom line

- **A fresh build did not compile, and the released testing build breaks at runtime.** On the
  unmodified worktree, `dotnet build TAOM.Tests --no-incremental -p:DisableModuleCopy=true
  -p:ModuleId=` gave one error: CS0115 at `TaomPartySizeModel.cs(52,37)`, "no suitable method found
  to override". v1.5.7 put a required `bool isCurrentlyAtSea` in front of `includeDescriptions` in
  `PartySizeLimitModel.GetPartyMemberSizeLimit`
  (`~/.taom-src/v1.5.7-202611101605/TaleWorlds.CampaignSystem.ComponentInterfaces.PartySizeLimitModel.cs:14`;
  the v1.5.6 form is `(PartyBase party, bool includeDescriptions = false)`). The patch notes do not
  mention it.
- **One of the three TAOM call sites compiled with a changed meaning.** `CareerPerkCheats.cs:81`
  passed `(party.Party, true)`. On v1.5.7 that binds as "at sea, no descriptions". The compiler
  cannot see it, and the binding gate cannot either. `PatrolRosterHook.cs:28` passed one argument
  and failed behind the override error.
- **The fix is three source edits and one test.** The override takes the new parameter and hands it
  to `base`. Both callers pass `party.IsCurrentlyAtSea`, which is what the v1.5.6 body read by
  itself, and the cheat names `includeDescriptions`. Behaviour is unchanged.
  `PartyMemberSizeLimitCallShapeTests` fails on a `true` or `false` literal passed by position to
  that method in any call under `Main`, `Client` or `Dependencies` that its scanner can read (it
  blanks comments and literals and reads balanced brackets; a bool variable is outside the rule).
  After the edits the same build gave 0 errors and 2,898 warnings.
- **A `TAOM.dll` built for v1.5.6 cannot serve v1.5.7.** `check_engine_member_refs.ps1` on the
  testing channel's v2.0.36 `TAOM.dll` reports 2 new misses:
  `PartySizeLimitModel::GetPartyMemberSizeLimit(PartyBase,Boolean)` and the same member on
  `DefaultPartySizeLimitModel` (4,912 refs checked). Every other DLL in that channel has 0 new
  misses. The fresh build has 0 unresolved (see Gates). What a player would see is inferred from CLR
  rules and was not run: see Players.
- **Every other binding resolves.** Strict binding gate on the working tree: 966 passed of 966, 0
  failed, 0 skipped. The member-level diff found 6 changed rows of 702, and none needs a further
  code change (below).
- **Vanilla now defines the two `str_last_seen_*` ids TAOM added in v1.5.6**, so TAOM's two rows and
  their 24 language rows are deleted. This was the item v1.5.6 left owed for the next bump.
- **The installed co-op mod does not resolve on v1.5.7.** Its `GameInterface.dll` (2026-10-29) has 2
  new misses. That mod is not TAOM's code (Out of scope).

## Players

The testing channel held v2.0.36, built for v1.5.6. **A tester's log confirmed the hang on
2026-11-10:** on v1.5.7.125802 a new campaign with v2.0.36 never left the loading screen, with
`MissingMethodException: ... GetPartyMemberSizeLimit(PartyBase, Boolean)` at
`PatrolRosterHook.FitToLimit` on every tick, because the application-tick shield catches it and the
load step runs again. **v2.0.37 is the build for v1.5.7.** The first point below is still inferred
from CLR rules and was not run:

- `TaomPartySizeModel.GetPartyMemberSizeLimit(PartyBase, bool)` no longer overrides the engine's
  three-argument method, so the engine runs vanilla's. Every TAOM party-size effect is lost without
  an error: culture feats, AI lord and caravan scaling, career passives, the Eye of Sauron host, the
  castle patrol size and the troop weight penalty.
- `PatrolRosterHook.FitToLimit` calls the removed two-argument method. The JIT compiles that method
  on the first `FindAppropriateInitialRosterForMobileParty` call, for any party, so the first party
  that takes a template roster throws `MissingMethodException`.

Testers need a build made from this branch or later before they take v1.5.7. A v1.5.7 build cannot
serve v1.5.6 either, for the same reason.
