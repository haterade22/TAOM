# Bannerlord v1.5.3: impact on TAOM

**Date:** 2026-09-15 · **Branch:** `bannerlord-1.5.x` (at `70517552`, v2.0.29) · **Engine:** client
and Modding Kit both v1.5.3, buildid 25302170, Steam beta branch, installed 08:15 to 08:16 ·
**Predecessor:** [v1.5.2-impact.md](v1.5.2-impact.md), one day earlier.

## Bottom line

- **Compile, bindings and the suite were green before anything changed.** `dotnet build` against
  the v1.5.3 references, 0 errors; 311 BindingVerification checks; the full suite 9,174 passed, 2
  skipped, 0 failed. A patch release that moved no bound signature.
- **The one real break was data, and no gate saw it.** The v1.5.3 `PartyNameplateWidget` gained the
  ship-banner widgets and dereferences `ShipBannerContainerWidget` in `OnUpdate` on the first frame
  and in `UpdateNameplatesVisibility` on every frame, with no null guard. TAOM ships clones of
  `PartyNameplateItem.xml` and `PartyPlayerNameplateItem.xml` (re-based on v1.5.2 the day before),
  and a clone replaces the vanilla file, so the property stayed null: a NullReferenceException on
  every party nameplate the moment the campaign map came up. Same shape as v1.5.0's
  `BloodFeudIconWidget` (commit `65bc90a2`). Both clones are re-based on the v1.5.3 files with
  TAOM's edits re-applied, and `PrefabCloneWidgetReferenceTests` now gates the class: every
  Widget-typed property attribute a vanilla prefab declares must survive in the TAOM clone that
  shadows it. Its first run also found `PartyTroopManagerPopUp.xml` missing
  `TertiaryInputKeyVisualParent`, which the engine guards with an early return, so the input-key
  hints in that popup had silently never shown; spliced in.
- **The member-level body diff found nothing else.** 355 bound members compared between the
  archived v1.5.2 decompile and the fresh v1.5.3 one: 343 identical, 3 changed, the rest the known
  unparsed constructors and property accessors the binding tests cover. Verdicts below.
- **Manifest parsing now throws where it used to fall over.** `XmlResource` (mbproj and
  `<Xmls>` rows) and `ModuleInfo.LoadWithFullPath` report line numbers and throw on a missing
  `Id`/`Name`/`Version`, a `<file>` without `id`/`name`, an `XmlName` without `id`/`path`, a
  game-type row without `value`, or a dependency row without `Id`. Every TAOM manifest, stub and
  mbproj passes. Comments inside `<IncludedGameTypes>` are now skipped instead of dereferenced.
  `MergeElements` and `CreateMergedXmlFile`, which TAOM's data depends on, did not change.
  `LoadWithFullPath` still never reads `DependedModuleMetadatas`.

## What moved

File level, ilspycmd nag line filtered: 18 of 57 shipping assemblies, 20 of 66 editor assemblies,
12 of 26 vanilla module satellites. Most of those by build number alone (4 to 8 diff lines).
Substantive: `TaleWorlds.CampaignSystem` (4,199 diff lines), `TaleWorlds.MountAndBlade` (404),
`TaleWorlds.ObjectSystem` (266, all in `XmlResource`), `TaleWorlds.Engine` (175),
`TaleWorlds.MountAndBlade.GauntletUI.Widgets` (181, the nameplate ship banner among them),
`TaleWorlds.ModuleManager` (145, assembly collection rewritten recursively plus the manifest
checks), `TaleWorlds.Library` (109), `SandBox.GauntletUI.AutoGenerated.1` (3,658) and the Native
`GauntletUI.AutoGenerated` pair (4,826 together). Steam stamped 4,636 files under `Modules`,
`bin` and `XmlSchemas`; the bytes are asset repacks (every `Native/AssetPackages/pack_*.tpac`,
`meshes_shared_*`, `gauntlet_ui.tpac`) and 309 language files. `_diff_1.5.2_to_1.5.3_*.txt` under
`E:\Decompiled_Bannerlord` hold the file-level lists.

Vanilla data TAOM reads or shadows, touched today: `Native/ModuleData/native_parameters.xml` (the
shield-arc renames; no TAOM module overrides any of them, `TAOM_Map`'s copy is an empty Kit stub),
`item_modifiers.xml` (+28 bytes), `global_strings.xml` and `native_strings.xml` (the Honor trait
rename to Deceitful; TAOM binds no trait-level string and overrides no crime model),
`SandBoxCore/ModuleData/items/{body_armors,weapons}.xml`, `Native/GUI/NativeSpriteData.xml`, four
prefabs: the two SandBox nameplates above, `Native/GUI/Prefabs/Order/OrderTroopItem.xml` and
`Order/Radial/OrderSetRadial.xml` (formation morale on order cards; TAOM clones neither).
`validate_moduledata.py`, `audit_action_set_parity.py` (0 gaps, 0 orphans) and
`audit_mount_parity.py` (read: every usage action bound) unchanged.
