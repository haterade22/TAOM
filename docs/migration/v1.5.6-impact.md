## Bottom line

- **A fresh build did not compile, and the released testing build breaks at runtime.** On the
  unmodified worktree, `dotnet build TAOM.Tests --no-incremental -p:DisableModuleCopy=true
  -p:ModuleId=` gave 4 errors: CS0534 and CS0115 on `TaomHowdahMachine` and `TaomMumakilPlatform`,
  because `UsableMachine.GetDescriptionText` gained an abstract `Agent requesterAgent` parameter
  (`~/.taom-src/v1.5.6/TaleWorlds.MountAndBlade.UsableMachine.cs:1178`; the v1.5.5 form is one
  argument). Behind that wall, four perk calls failed (CS1503, CS1620, CS1615, CS1744):
  `MobileParty.HasPerk` lost both `out Hero` overloads (now `HasPerk(PerkObject, bool
  checkSecondaryRole = false)`, `MobileParty.cs:3281`), and `PerkHelper.AddPerkBonusForParty`,
  `AddPerkBonusForCharacter`, `AddPerkBonusFromCaptain` and `AddEpicPerkBonusForCharacter` moved
  `BattleEnvironment` to a trailing optional parameter (`Helpers.PerkHelper.cs:85` and `:104`).
  The call sites: `PrisonerEscapeAdapter.cs:132`, `TaomSiegeEventModel.cs:28-29`,
  `ForestSightContributor.cs:36` and the two machine overrides.
- **The fix is five small source edits plus one test pin**, all in `12b010626`
  (`ForestSightContributorTests.cs:74` pins the call text). Behaviour is unchanged: the old calls
  passed `Any` or the party's current environment, and both are the new defaults. After the edits,
  `dotnet build TAOM.Tests --no-incremental -p:DisableModuleCopy=true -p:ModuleId=` gave 0 errors and
  2,676 warnings (CS8618 and CS0414 style items; not baselined against trunk).
- **A `TAOM.dll` built for v1.5.6 cannot serve v1.5.5.** `check_engine_member_refs.ps1` on the fixed
  build against the v1.5.5 BUTR reference assemblies reports 3 new misses (`HasPerk(PerkObject,
  Boolean)` and the two new `PerkHelper` forms), and the two-argument `GetDescriptionText` leaves the
  v1.5.5 one-argument abstract member unimplemented. The testing channel moves to v1.5.6 as a whole.
  Whether any player must stay on v1.5.5 is a question for Mike.
- **`BattleEnvironment` lost `None`.** `Land`, `Naval` and `Any` moved from 1, 2, 3 to 0, 1, 2
  (`TaleWorlds.Core.cs:2891` in the v1.5.5 dump against the v1.5.6 one). Every constant compiled into
  a v1.5.5-built binary now reads as the next member down: a baked `None` reads as `Land`, `Land` as
  `Naval`, `Naval` as `Any`, and `Any` (3) is no defined value. The visible case is the
  `CustomBattleCombatant` constructor default, which the compiler bakes in at the call site: an old
  `TAOM.dll` passes `Land` as 1, which v1.5.6 reads as `Naval` (`HostReviewMissionLauncher.cs:104`
  and the parked `TaomShaderGameManager.cs:117,120`). A rebuild rebinds it to 0.
- **Every other binding still resolves.** Strict binding gate on the final tree: 818 passed of 818,
  0 failed, 0 skipped (Patch123's rows are gone; the #1037 and #1040 rows are new; see Gates).
  The 27 bound members whose bodies changed need no further code change (below), and all 18
  transpilers keep their anchors.
- **Combat and mount patch notes do not reach TAOM.** Every number in them changed only in
  multiplayer code or multiplayer data (see "Combat patch notes").

Two rows the tool cannot read, both verified by hand:

  `TroopRosterInterface.HandleOnRecruitmentDone`; that body is identical and the engine members it

not a fresh run.

## Combat patch notes

Every combat and mount number in the v1.5.6 notes changed in multiplayer only. TAOM never loads the
multiplayer game type, and its charge penetration default of 0.4 still equals the single-player value.

- **Horse charge penetration 0.40 to 0.43:** `MultiplayerAgentApplyDamageModel.cs:180-183` returns
  0.43f (the v1.5.5 dump, `TaleWorlds.MountAndBlade.cs:65453-65456`, returned 0.4f).
  `SandboxAgentApplyDamageModel.cs:1102-1105` and `CustomAgentApplyDamageModel.cs:252-255` still
  return 0.4f (the Sandbox body is identical at v1.5.5 `:1102`).
- **Head and neck piercing 1.25 to 1.15:** `MultiplayerAgentApplyDamageModel.cs:266` and `:283` moved
  from 1.25f to 1.15f; `SandboxAgentApplyDamageModel.cs:1296` and `:1313`, and
  `CustomAgentApplyDamageModel.cs:335` and `:352`, stay 1.25f. TAOM has no body-part override.
  `MissionCombatMechanicsHelper` decompiles with 0 diff lines. Neither constant is in native code
  (no `1.15f` in `.text`, `.rdata` or `.data` of either native build).
- **Horse speed cuts, troop speed edits, Big Game Hunter and Feller, weapon pieces:** the `mp_*` item
  data in Native `mpitems.xml`, `mpclassdivisions.xml` (both Native `SubModule.xml`, MultiplayerGame

## Vanilla changes TAOM inherits

- **Camaraderie** dropped from AddFactor 2 to 1, which changes the number `BattleRelationAdapter.cs:96`
  reads.
- **Combat simulation.** `TaomCombatSimulationModel` inherits `GetBattleAdvantage` and
  `GetSettlementAdvantage` (Pre-Battle Maneuvers, and On The March for land only).
  `MapEvent.SimulateSingleTroopHit` now passes `Land` or `Naval` instead of `Any` for settlement
  troops into its `SimulateHit`.
- **Captor parties no longer vanish** after the player is made prisoner:
  `CampaignTickCacheDataStore.UpdateVisibilitiesBasedOnPoint` honours `IsVisibilityPersistent`, and
  `TaomMapVisibilityModel` does not override it.
- **Field parley** (new): `DefaultEncounterModel.CanMainHeroDoParleyWithParty` now accepts a lord party
  within the main party's seeing range, and the modifier key is `MapParleyModifier`, bound to Left
  Ctrl. Settlement parley changed from path distance (`MapDistanceModel.GetDistance`) to straight-line
  distance (`Position.DistanceSquared(GatePosition)`), so the option can appear across a river or
  ridge. With Left Ctrl held, a click on any party or settlement tries to parley and issues no move order:
  an eligible target opens a parley, and anything else prints vanilla's refusal text, or "Cannot parley
  with this party." (or "...settlement.") when the refusal has none, as for a friendly town or party. A
  click on open ground still moves. TAOM's turbo time control is also Ctrl-gated
  (`TimeAccelerationService.cs:72`), so a turbo click (Ctrl + Space) would have parleyed instead of
  moved; #1040 makes it an ordinary click again in this release: Patch124, a postfix on the private
  `MapScreen.IsParleyClickReleased()`, answers false while turbo is latched, so `HandleMouse` takes its v1.5.5
  click branch. The parley icon on nameplates is left as vanilla draws it (cosmetic). Inferred from code,
  not checked in game.
- **Vanilla fixes beside TAOM hooks, no overlap:** the blood-feud notice when the executed hero is the
  player (Patch14's target is unchanged), the AI noble defending a settlement, and null-tolerant
  `ContainerLoadData` for saves made after removing mods (SaveShield and Patch61 targets all resolve
  and are still needed). The village-raid battle crash fix was not located in any managed vanilla
  diff; absence holds only within those diffs.
- **A vanilla gap:** `HeroHelper.GetLastSeenText` reads `str_last_seen_encyclopedia_entry_leading_army`
  and `str_last_seen_encyclopedia_entry_at_sea_leading_army` for an army leader, and no installed
  module defines either. `FindText` returns its "Text with id ... doesn't exist" text for a missing id,
  so a known AI army leader's encyclopedia page would show that error. The only caller is the
  encyclopedia hero page (`TaleWorlds.CampaignSystem.ViewModelCollection.cs:60959`, which skips the
  player's own page), so the check needs another lord's page. TAOM now defines both ids (below).
