# Lord Skills

## Overview

Lore-driven skill values + personality traits for every TAOM adult lord across all 17 cultures (~880 NPCs). Built on a TAOM-owned SkillSets system (`taom_lord_skill_sets.xml`) referenced via each NPCCharacter's `skill_template` attribute, plus a 35-archetype + ~85-canonical override scheme generated from a single Python source-of-truth.

## Why This Exists

- **Vanilla behavior:** every Bannerlord hero NPCCharacter references one of vanilla's ~50 generic SkillSets (`spc_dandy_skills`, `spc_swordsman_skills`, etc.). These are tuned for vanilla calradian factions and bear no relation to Middle-earth lore. Boromir would inherit `spc_dandy_skills` → OneHanded=140, Roguery=150, Charm=230 — a "socialite and master of courtly graces" instead of a master swordsman + Captain-General.
- **TAOM requirement:** every named Tolkien character should have skills that match their canonical role (Boromir = peak swordsman; Galadriel = peak charm/leadership/wisdom; Dáin II = peak dwarven king; etc.). Every TAOM-invented supplementary lord should fit an archetype matching their bio role.
- **Without this feature:** in-game encyclopedia shows Boromir at OneHanded=145 / Leadership=207 — bad for immersion and bad for gameplay (player can't trust hero stats to reflect lore).

## Architecture

### Design Challenge

Two engine quirks made the obvious approach (just edit `<skills>` blocks) fail:

1. **Hero NPCCharacters ignore explicit `<skills>` blocks** — only `skill_template="SkillSet.X"` is honored at hero generation. Hand-editing `<skills>` is dead code.
2. **Same-ID NPCs across additive XML sources resolve by load order** — `characters/lords.xml` loads AFTER `lords.xslt`-transformed vanilla per SubModule.xml, so the XSLT overrides for the 11 lord_1_X_Y IDs that exist in both files are shadowed by `lords.xml`. Hand-editing the XSLT for those IDs is also dead code.

### Solution Approach

Create TAOM-owned SkillSets in a new module-registered XML file. Swap every adult NPCCharacter's `skill_template` to a TAOM SkillSet. Use a single Python generator as the source-of-truth so canonical overrides + archetype defaults stay in sync across the data files.

### Component Diagram

```
tools/apply_culture_skills_traits.py    (source of truth — CULTURES dict)
            │
            ├──── Main/_Module/ModuleData/taom_lord_skill_sets.xml
            │        └── 120 SkillSets (35 archetype + 85 canonical)
            │
            ├──── Main/_Module/ModuleData/characters/lords.xml
            │        └── skill_template attr swap per NPC + populated <skills>/<Traits> blocks
            │
            └──── Main/_Module/ModuleData/lords.xslt
                     └── same skill_template attr swap per NPC template
                     │
            (Engine reads skill_template → looks up SkillSet → assigns hero stats)
```

Full pipeline + recipes in [`docs/ai-includes/lord-skills-authoring.md`](../ai-includes/lord-skills-authoring.md).

## Configuration

### Source of truth: `tools/apply_culture_skills_traits.py`

| Dict | What it defines |
|---|---|
| `BASE_ARCHETYPES` | 35 archetype templates (skill values + trait values). Edit to retune an archetype across all NPCs that use it. |
| `CULTURES[<key>]` | Per-culture entries: `culture_id`, `lore_name`, `race`, `keyword_archetypes`, `canonical`. |
| `CULTURES[<key>]['canonical'][<npc_id>]` | Per-NPC override: either full `skills=` + `traits=` OR `archetype='X'` only OR archetype + partial override. |

### Generated artifact: `Main/_Module/ModuleData/taom_lord_skill_sets.xml`

DO NOT hand-edit. Regenerated by every script run from `BASE_ARCHETYPES` + canonical entries. 120 SkillSets:
- `taom_<archetype>_skills` — one per archetype (e.g., `taom_lord_skills`, `taom_dwarf_king_skills`, `taom_nazgul_skills`)
- `taom_canonical_<npc_id>_skills` — one per canonical NPC with explicit `skills=` (e.g., `taom_canonical_lord_1_75_skills` for Boromir)

Registered in [`Main/_Module/SubModule.xml`](../../Main/_Module/SubModule.xml) as `<XmlName id="SkillSets" path="taom_lord_skill_sets"/>`.

- Bannerlord v1.4.5 SkillSet schema

## Tests

| Test | How to run |
|---|---|
| XML well-formedness (3 files) | `python -c "import xml.etree.ElementTree as ET; ET.parse('Main/_Module/ModuleData/taom_lord_skill_sets.xml')"` (repeat for lords.xml + lords.xslt) |
| Script idempotency | Run `--all-cultures --apply` twice; second run should produce zero diff |
| In-game smoke (THE REAL TEST) | Launch Bannerlord → New campaign → Encyclopedia → Heroes → filter by culture → check canonical hero's Skills panel matches SkillSet base + ~5-10 level growth |

The XML well-formedness check is a sanity smoke. The in-game test is mandatory before ship — the engine's behavior around `skill_template` precedence is the whole reason this feature exists.

## Save Compatibility

Hero skills bake at hero CREATION. Existing campaigns keep their old (vanilla SkillSet) values. New campaigns + un-spawned heroes use the new TAOM SkillSets. Document this in any user-facing release notes.
