## 1. Scope and decisions

**Scope (maintainer, binding):**

1. **Gate repair and gate levels.** Repair a broken or damaged gate between waves; each level adds hit points. Spike S4's recipe is the base; its fallback is a barricade entity.
2. **High towers.** The towers already on the walls, no new models. Level 1 posts archers on the tower, level 2 posts more, level 3 adds a volley.
3. **Field care.** Heals the troops that stand, bought between waves.
4. **Elven Volley.** Bought between waves, used during a wave on a cooldown; arrows only, no soldier spawns; level 1 aims itself at the densest group of attackers near the walls, an upgrade aims at the crosshair; each arrow aimed at its own attacker; scripted missiles through `Mission.AddCustomMissile` from recorded points behind the parapet; the missile a Lothlorien elven arrow (Mike named `wm_elven_arrow_q1v3` to `q4v3`; OQ3); each arrow owned by a standing defender (Slice 9 kill-owner rule). It shares its code with the level 3 tower volley.
5. Everything priced and levelled in JSON; the report and the leaderboard plan kept in step; a `[Check]` line and a `1079.toml` row per mechanic; the bot buys each mechanic; player text as `{=KEY}default`, seeded with `--seed-only` only (translations go to #763).

Constraints as Phase 2: ADR-002, ADR-007, TDD, no `#region`, `[Obsolete]` or `#if`, `Main/IoC.cs` and `Main/SubModule.cs` untouched (the XML `Main/_Module/SubModule.xml` is a different file), `{=TAOM_LD_*}` keys, co-op absent, Fords code untouched (its pure geometry is called, never edited).
