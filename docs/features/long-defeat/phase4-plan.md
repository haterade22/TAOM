## 1. Scope and decisions

**Scope (maintainer, binding):**

1. **Armoury.** A place the lord walks to (recorded point `armoury`, `{x,y,z,fx,fy}`). Between waves, near it, a prompt opens an armoury panel that sells personal gear sets (armour and weapons) for the lord's own agent, from the defending faction's own items. The change is immediate on the live agent. Bought gear persists for the run: at each respawn or rise the lord wears it.
2. **Engineer's yard.** A place the lord walks to (recorded point `yard`). Between waves it sells a mangonel or trebuchet placed at a deployment point the player chooses (the scene's own `DeploymentPoint`s). The player or the AI can crew it.
3. **The death rule.** When the lord falls in a wave he takes over another soldier for the rest of the wave; at the next intermission he rises at the keep point in his bought gear. The run continues while defenders stand.
4. Everything priced in JSON; the run report (schema 2, additive) and the leaderboard (#1080) kept in step; a `[Check]` line and a `1079.toml` row per mechanic; the bot reaches or buys each mechanic; player text as `{=KEY}default`, seeded with `--seed-only` only (translations go to #763); a mechanic is offered only when it works end to end and stays hidden for a fortress with no recorded point.

Constraints as Phases 2 and 3: ADR-002 (entry points under 150 lines, a partial counts all its files), ADR-007, TDD, no `#region`, `[Obsolete]` or `#if`, never key on `Agent.Index`, off-thread callbacks write through `RunOrDefer`, gates and engines read from `MissionObjects` or held lists and never `ActiveMissionObjects`, `Main/IoC.cs` and `Main/SubModule.cs` untouched, Fords code untouched, co-op absent.

**Findings that shape the decisions (read this turn):**

- **Phase 1's death path today.** The launcher calls `SetPlayerCanTakeControlOfAnotherAgentWhenDead` (`LongDefeatMissionLauncher.cs:90`). A person presses `E` (game key 16, `Kick`, `CombatHotKeyCategory.cs:24`, `:147`) while following a soldier the engine accepts (`MissionScreen.cs:1810-1814`; `Mission.cs:6393-6400`), and `AdoptIfNew` adopts the new body (`LongDefeatDirector.cs:251-270`). At a clear the lord respawns only when **no** main agent stands (`LongDefeatDirector.Effects.cs:270-275`), so a lord who took a soldier stays in that soldier's body, in that soldier's gear, through the intermission and the next wave. The autorun bot never takes over (it cannot press `E`), so every unattended death so far was a respawn. Under autoplay every adopted body ends AI-driven: `AdoptMain(aiDriven)` ends with `main.Controller = AgentControllerType.AI` (`LongDefeatBattlefieldAdapter.cs:504-505`), called with `_plan.Options.Autoplay` (`LongDefeatDirector.cs:257`), and the engine's `IsPlayerControlled` is false for such a body. So in a bot run no agent reads as player-controlled once adoption ran, and a later `Controller = AI` on that body is a no-op (the setter returns when the value is unchanged, `Agent.cs:1242-1244`).
- **No bought hero exists.** The shop sells packs and fortifications only (`shop.json`); "the armoury and a bought hero as general (Phase 4)" was cut from Phase 2 (`phase2-plan.md:545`). When the main agent is removed the engine hands every formation to the AI (`Mission.cs:3040-3043`) and nothing clears `Team.GeneralAgent`, so the general stays the dead body. Across the whole of `TaleWorlds.MountAndBlade.dll` (the engine critic's full decompile), `GeneralAgent` only doubles an agent's battle importance (`Agent.cs:2555-2567`), which the morale model reads at a death (`CustomBattleMoraleModel.cs:13`, `:53`), and feeds two sergeant-only messages that test it for null (`BehaviorComponent.cs:89-95`, `TeamAIComponent.cs:330-333`); the other readers (`GeneralsAndCaptainsAssignmentLogic`, `SiegeDeploymentMissionController.cs:89-91`, `BattleDeploymentHandler.cs:109-114`, `SiegeDeploymentHandler.cs:330`) are absent from this mission, and no SandBox behaviour or view is loaded. - **Helm's Deep's defender sites take a mangonel, not a trebuchet.** The four defender `DeploymentPoint`s near height 10 (hidden until the 2026-11-06 rework, visible since; `scene.xscene:3869`, `:16232`, `:13080`, `:3797`, at (214.6, 156.0), (192.7, 180.7), (264.1, 119.2), (237.5, 136.3)) each have a `mangonel_b_spawner` within 1 m (`:6602`, `:2221`, `:13745`, `:12114`) and a `ballista_b_spawner` within 1 m (`:393`, `:8119`, `:4501`, `:17230`). The brief's "neither scene has a ballista spawner" does not match this scene file (OQ9).
