# Dinen

## Overview

Dinen ("silent" in Sindarin, as in Rath Dínen) answers the Modding Kit's assert and warning boxes from inside the
editor process, from the moment the Kit constructs its modules. It lives in `TAOM.Dependencies` and runs only when
that DLL loads from `bin/Win64_Shipping_wEditor`. The game and the dedicated server never run it. Issue: #1627.

It does not reach the Kit's native start-up phase. On 2026-11-27 the Kit process started at 11:56:52, Dinen hooked at
11:59:38 and then answered 267 boxes until the main menu; the boxes of the first three minutes (an `ASSERT` at
`rglBuffer.cpp:899`, `RGL CONTENT WARNING` boxes for missing materials) came before any module existed. Run
`tools/assert_auto_ignore.py` with the Kit for that phase. A native DLL loaded at process start is #1629.

## Why This Exists

- **Vanilla behavior:** the Kit stops on every `ASSERT`, `SAFE ASSERT`, `RGL ...`, `Always Ignore?` and
  `Safe Mode` box until someone clicks it.
- **TAOM requirement:** Kit work (scenes, prefabs, tpac saves) needs an unattended load.
- **Before Dinen:** `tools/assert_auto_ignore.py` (started by a desktop `.bat`) clicks each box from outside the
  process after the box opens. It still runs and still covers what Dinen cannot: the game client
  (`Bannerlord.exe`), the launcher and a `*_*` box that Watchdog shows from its own process (owned by `csrss.exe`).
  Dinen answers the `*_*` upload question that `TaleWorlds.Native.dll` itself asks inside the Kit.

An answered assert is not a pass. The causes stay; judge asset work with a game launch and read `rgl_log`.

## Architecture

### Solution Approach

`Dinen.InstallIfEditor()` runs in the `TAOM.Dependencies` `SubModule` constructor, after `GameVersionNotice` (which
skips the Kit). It never throws: the Harmony work sits in a NoInlining helper inside its try. The module's
`ModulesToLoadAfterThis` lists Native, so the hook is in place before the Native submodules construct. Every box the
native engine raises before that (its resource loading, and the module XML that `Module.LoadSubModules` reads before
it constructs any submodule) still opens; see the Overview. Once per process it does three things:

1. **MessageBoxA hook.** It reads the import table of the loaded `TaleWorlds.Native.dll` and points its
   `USER32.dll!MessageBoxA` slot at a managed delegate. On v1.5.7 the client and wEditor builds both import
   `MessageBoxA` only, with no delay-load table (checked 2026-11-27 with a PE read of both DLLs). The delegate asks
   `DinenPolicy.AnswerFor(caption, style)` and returns the answer without showing the box, or calls the real
   function.
2. **`Debug.Assert` and `Debug.FailedAssert` prefixes** (TaleWorlds.Library) that return false. `Debug.Assert` is
   `[Conditional("_RGL_KEEP_ASSERTS")]` (`TaleWorlds.Library.Debug.cs:109`): the client build of
   `TaleWorlds.MountAndBlade.dll` has 0 calls to it, the wEditor build 2,279 (ilspycmd, 2026-11-27). The wEditor build
   also calls `TaleWorlds.Engine.MBDebug.Assert` 38 times; that goes straight to native, so only the MessageBoxA hook
   answers it. A call site the JIT inlines also skips the prefixes and reaches the hooked box.
3. **`GetActionCodeWithName` prefix** on `ManagedCallbacks.ScriptingInterfaceOfIMBAnimation`
   (TaleWorlds.MountAndBlade.AutoGenerated): while `GetNumActionCodes()` is 0 it returns -1 instead of calling
   native. QuietEditor reports a Kit crash there on v1.5.7. TAOM has not reproduced that crash (UNVERIFIED), so the
   prefix writes one diag.log line for each action name it answers. If `ActionIndexCache`'s static constructor runs
   then, its `static readonly` fields stay -1 (`act_none`) for the rest of the Kit process. The 2026-11-27 Kit run did
   that: from 11:59:42 the prefix answered `act_pickup_down_begin` and the rest of the table, and muted the matching
   `Index >= 0` assert at `MBAnimation.cs:369`
   (`Main/Features/HeroRace/ActionIndexCacheRepair.cs` describes the same state). The native lookup also returns -1
   for a name it does not know.

`Dinen.StopWarningDumps()` runs in `OnSubModuleLoad` and sends the engine command
`debug.donot_create_dumps_for_warnings`, so warnings write no dump files.

### Answers

`DinenPolicy.AnswerFor` takes the box caption (trimmed, exact) and the low four bits of its style:

| Caption | OK styles (0, 1) | Abort/Retry/Ignore (2) | Yes/No (3, 4) | Cancel/Try/Continue (6) |
|---|---|---|---|---|
| `ASSERT`, `SAFE ASSERT`, `Safe Mode`, `*_*`, any caption containing `RGL` | OK | Ignore | No | Continue |
| `Always Ignore?` | OK | Ignore | Yes | Continue |

Every other caption and style (5, Retry/Cancel) shows the box. Abort and Retry are never answered.

The styles the v1.5.7 wEditor `TaleWorlds.Native.dll` passes, read with `tools/native_decompile.py` on 2026-11-27:

| Caption | Style | Dinen's answer | What the engine then does |
|---|---|---|---|
| `ASSERT`, `SAFE ASSERT` | `0x52012` (Abort/Retry/Ignore) | Ignore | takes its ignore branch |
| `Always Ignore?` | `0x40001` (OK/Cancel) | OK | stores "always ignore" for that assert |
| `RGL CONTENT WARNING`, `RGL WARNING` | `0x41030` (OK) | OK | closes the box |
| `Safe Mode` | `0x40004` (Yes/No) | No | safe mode stays off (Yes runs the enable callback) |
| `*_*` | `0x40004` (Yes/No) | No | uploads no crash files |

So "always ignore", the answer `tools/assert_auto_ignore.py` gives with its first button, comes from OK; the Yes branch
covers only a Yes/No style the engine does not use today. QuietEditor answers No there, which is not a button on an
OK/Cancel box. The Python tool answers by button position and exact title, so it can differ from this table on a style
or caption the engine does not use. The `*_*` effect is read from the box text, not traced.

Each answered box, muted assert and action-code return writes one line to
`Modules/TAOM.Dependencies/diag.log` under the tag `Dinen`. `LogRepeatLimiter` (512 lines) writes a repeated line
once and does not report the repeat count. Past 512 distinct lines it writes every line. The hook and patch results
are on the same tag.

## Key Files

| File | Purpose |
|------|---------|
| `Dependencies/Foundation/Dinen.cs` | Editor check, import-table hook, the three Harmony prefixes, the dump command |
| `Dependencies/Foundation/DinenPolicy.cs` | Pure decisions: the answer table, the import-slot search |
| `Dependencies/SubModule.cs` | Calls `InstallIfEditor` in the constructor and `StopWarningDumps` in `OnSubModuleLoad` |
| `TAOM.Tests/Infrastructure/Dependencies/DinenPolicyTests.cs` | Answer table (with the engine's real styles), a synthetic PE image for the slot search, the parameter-name pins of the three prefixes, and a `BindingVerification` test of the action-code target |

## Testing

- `dotnet test TAOM.Tests -p:DisableModuleCopy=true -p:ModuleId= --filter FullyQualifiedName~DinenPolicyTests`
- The native hook and the prefixes have no behaviour test: they need the Kit process.

## How to verify in game

1. Build with `./build.ps1`, so `TAOM.Dependencies.dll` reaches `Modules/TAOM.Dependencies/bin/Win64_Shipping_wEditor/`.
2. Start the Modding Kit with TAOM enabled, and `tools/assert_auto_ignore.py` (or the desktop `.bat`) for the start-up
   phase.
3. Expect boxes to open, and the tool to click them, only before Dinen's first log line.
4. Open `Modules/TAOM.Dependencies/diag.log`. Expect a `Dinen` line `MessageBoxA hooked in 1 import slot(s)`, a line for
   the dump command, and one `answered` line for each box the Kit did not show after that. Passed on 2026-11-27: the
   hook line at 11:59:38, `debug.donot_create_dumps_for_warnings: Done`, and 267 `answered` lines to the main menu.
5. Start the game client. Expect no `Dinen` line from that process: the client loads the DLL from
   `Win64_Shipping_Client`.

## Provenance

Ported from [QuietEditor](https://github.com/Urien586/QuietEditor) v1.2.0 (commit `01dee8c9`, MIT). Its two C#
files were read in full on 2026-11-27: no network, no file writes, no install step. Its prebuilt
`src/lib/0Harmony.dll` was not used; TAOM.Dependencies carries Harmony 2.4.2. Not taken: the separate module (its
manifest loads it after Native; `TAOM.Dependencies` loads before), the `MessageBoxW` hook (the engine does not
import it) and the answer No to `Always Ignore?`. Row:
[provenance-register.md](../reference/provenance-register.md).
