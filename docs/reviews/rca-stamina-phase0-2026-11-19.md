## Root-cause pattern

Rows 1, 4 and 5 share one habit: a name stood in for a read of what it covers. `IsLive` was trusted at mission end because it was the guard, `DefendMask` because it was the mask, and "the strip rule" because both paths called it. Rows 2 and 6 share another: text written from the plan was not read again against the code that came later.

## Why each reviewer missed these

- **The builder** wrote the teardown as the mirror of the lock (take, then give back) and did not list the engine's state at each exit, which `lessons/misc.md` "A mission-scoped write or reset is chosen from every way the engine leaves the mission" asks for. The parse and the hint are plain repeats of recorded lessons that were not read before the code was written: the lesson headings for `gamemodels-services.md`, `testing-qa.md` and `localization-ui.md` were not listed for this work, only those for missions and adapters.
- **Lens 5** and **lens 2** both found row 1, from different ends (the call chain and the zeroed pointers). Lens 2 found rows 4 and 6. Lens 7 found row 2. Lens 5 found row 3 in the first wave and row 5 in the convergence pass.
- **The plan's three critics** reviewed the design before the code existed, so none could see rows 1 to 5.
