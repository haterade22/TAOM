# RCA: ADR-011 batch 1 review (#647, 2026-09-23)

## Top-line

`/deep-review` of ADR-011's first batch ran six lenses in two waves (Standards, Engine
compatibility, Data flow and Tooling, then Efficiency, Completeness and Design) and a convergence
pass over the fixes. It confirmed 22 defects, all fixed before the commit. A Codex adversarial
review (gpt-6-astra, ultra) then found 8 more, 0 HIGH, 6 MED and 2 LOW; all 8 held up when
reproduced, and all are fixed. Two of the 30 reach far past the change under review:

- **Nine PreToolUse gates had never blocked anything in a live session.** They printed
  `{"permissionDecision": ...}` at the top level of their JSON. Claude Code reads a PreToolUse
  decision only under `hookSpecificOutput` (hooks docs, "PreToolUse decision control"), so it ignored
  every deny and ask they returned: the destructive-git and broad-staging prompts, the CHANGELOG,
  tracked-files, ModuleData, native-DLL, doc-drift and commit-label gates, and `/freeze`'s boundary.
  Proven live: with a debug dump in the commit-label gate, the gate returned a deny in 0.25 s and the
  commit ran anyway. After switching that gate to the nested form, the same command was refused.
- **One non-cp1252 character in a command switched off every Python-parsed gate.** Hook Python read
  its piped stdin in the Windows ANSI code page, `print(command)` raised inside a bare
  `except: pass`, the command came back empty, and the gate read it as "not a commit" or "not a
  push". With HEAD's `_pybin.sh`, `NOTE=→ git push --force origin bannerlord-1.4.5` passed the
  force-push block (rc 0, silent); with the fix it is refused.

The two were found together. The Tooling lens proposed a probe for the encoding gap; running that
probe live showed a gate returning deny and the harness proceeding, which exposed the first.

## Root-cause pattern: a gate's green was a claim, not an observation

F1, F2, F5, F6, F20, C1 and C6 share one shape. Each gate was verified by something that could not see it
fail where it runs:

- F1: the tests matched text that the dead form also contained, and no tool call was ever shown
  refused;
- F2: every payload was ASCII;
- F5: a missing heading yields zero rows, and zero rows pass;
- F6: the CI step was never seen running on the branch the commits land on;
- F20: no test sent a gate the multi-line command it meets in practice;
- C1: the timeout check only timed hooks that launch a tool, so a slow git loop was never timed;
- C6: the frontmatter check lived in a suite that the new CI workflow does not run.

F4 is the same fault one level up: a hand-kept list that agreed with its source only on the day it
was written.

A second pattern covers C2, C3, C4 and C6: each gate read a language (shell, Markdown, YAML) with
a line regex that approximates it, and valid but unusual input broke the approximation. Read the
language with its parser, `shlex`, a scanner that follows the documented Markdown rules,
`yaml.safe_load`, and test the unusual forms the language allows.

The rule that closes the first class, now in `.claude/rules/hook-authoring.md` "Prove a gate live": a gate
is done when an event it must stop has been shown stopped in the environment it guards. For a hook,
that is a live tool call the harness refused; for CI, a run on the branch the work lands on. Pair it
with a test that fails when the gate's own input goes missing (an empty command, a missing heading,
an unread import).

## Why each lens found what it found

- **Standards (1):** stale references, dashes, hardcoded caps. Its hook check is "run
  `test_hooks.sh`", which was green for the dead form.
- **Engine compatibility (2):** F11 and F12, by reading the owning docs and the village tool.
- **Data flow (5):** F4, F6, F13 and F14, by following each fact to its consumer; it did not follow
  a hook's output into the harness.
- **Tooling:** F2, F3, F5, F8, F10, and the probe that exposed F1.
- **Efficiency (3):** F7.
- **Completeness (4):** F17, F18, F19, and the missing RCA and CHANGELOG entries.
- **Convergence pass:** F20, F21 and F22, by driving each rewritten gate with hostile input and
  parsing its output as the harness would. It also re-checked the import depth against the docs
  (four hops, as coded).
- **Design (6):** proposals, not defects. Four were applied with Mike's approval: the narrowed
  `harness-facts.md` paths, the `triage-needs-ingame` label as the smoke backlog, `attribution` in
  `settings.json`, and the JSON handshake for `scan.sh`. The catalog restatements were removed.

No lens could have found F1 by reading. Every gate matched the contract `harness-facts.md` stated,
and the contract itself was wrong. It took a live tool call.
