# RCA: great elk mount (deep review, 2026-09-22)

## Top-line

`/deep-review` of the great elk (#636): a horse-skeleton reskin built as the war ram, with `Monster.taom_elk` on the
ram's action set `as_war_ram` (the ram's head-butt plays as an antler charge), a cloned `Main/Features/Elk/`, two
Armory items, and the Mirkwood cavalry, Thranduil, the Mirkwood lord templates and the `elk_rider` career start
pointed at the elk. Seven lenses in two waves of four at most (wave 1: Standards, Engine, Data flow, XML; wave 2:
Efficiency, Completeness, Design), all on the deep-reviewer definition, then one convergence pass.

**No CRITICAL or HIGH, and no engine incompatibility.** Engine verified 25 API and lifecycle claims against the
installed v1.5.3 DLLs, including the party-icon mount path, the saved hero battle equipment, the rider scaling by
`body_length`, and two Monsters sharing one action set. XML ran eleven gates; the one failure is pre-existing
localization debt owned by other features. Efficiency found nothing in the changed code.

Findings in the change: **2 MEDIUM, 9 LOW**, all fixed the same night. Owed outside code: 2 MEDIUM (Kit), in-game
smoke, paid translations. Follow-ups on pre-existing code: #637, #638, #639, #640, #641, #642.

## Root-cause patterns

**Cloning brings the donor's defects with it (F4, F5, F6, F11).** The elk was built by copying the war ram, which
was the right call for behaviour and the wrong one for text: three statements the ram's files make without evidence
(a suffix derivation, a test pin, a translation step) arrived in the elk's files word for word, and an old test
idiom came along too. A clone's code is proven by the donor's tests; its prose is proven by nothing.

**Tracing forward from the change, never backward to what copies or depends on it (F1, F2, F9).** Each lens that
found these asked "who else reads the thing you changed": a generator that copies the roster, a donor whose set is
now shared, a register that lists the donor's consumers. The build traced every id the elk USES and none of the
places that USE what the elk touched.

## Why each agent missed these

Nothing was missed by a lens: every finding above came from one. The lenses that did not report a given finding
were outside its domain (Efficiency and Design report no documentation defects; Standards reads C# and harness
files, not rosters).

## Feedback memories to codify

None beyond the lessons: both patterns are process rules for building from a donor, and the lessons files are where
the next build of a creature reads.
