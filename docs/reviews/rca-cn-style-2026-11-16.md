# RCA: Chinese AI drafts follow the Chinese team's text (#1421)

Findings from the review of #1421: `tools/build_translation_reference.py` writes an English and team text pair
for every row of ours that carries the Chinese team's text, and `translate_with_claude.py` gives each CNs and CNt
batch the team's terms and style examples from it (`tools/_team_reference.py`). Tools, tests and docs only, no C#
or XML, so it ran as tier 2: the tooling lens at `high`. Codex did not run: it has had no usage since 2026-11-15,
and the maintainer said to skip it. The lens rated one finding HIGH by its rule for a writer that can lose data;
git restores the file, and the fix is small and tested, so no second wave ran. Each finding was read again against
the files, and rows 2 and 3 against the shipped `cns.json`, before it was fixed.

Rows 9 to 16 are from the review of the re-draft itself: 5,211 CNs and CNt rows across TAOM and the live
TAOM_Map and Armory files. Live data makes it tier 1, so Lens 5 (data flow), Lens 7 (XML) and Lens 2 (engine
compatibility) ran at `max`; Codex was skipped for the same reason. Lens 2 found no row the engine would fail on
(tokenizer, conditional parser, `[...]` stripping, loader structure, fonts). Each Lens 5 count was measured again
before the fix. Rows 17 to 19 are from the gate run and a name check after the second draft. Lens 5's HIGH required a
second wave (Tooling, Efficiency, Completeness, Design, at `high`); rows 20 to 24 are its findings, each checked
against the files before the fix.

## Not applied

- Lens 2 F3, the rest: the gate does not check the order of conditional tokens or that `simkai` has each glyph. No row hits either today; the order check needs a token parser. No issue: the translation backlog (#1129) carries the next pass, and these checks go in with it if a row needs them.
- Lens 2 F1: the paid run also drafted 1,190 rows per language that were still English (encounter 435, encounter_lord 243, xslt 243, module 218 and others). The maintainer asked for Chinese like the team's, so they stay; the commit body counts them.
- Tooling F7: `estimate_cost` does not count the guide (about 2,100 characters per 40-entry sentence batch). The run prints the real cost from the API's usage, and the error in the estimate is small, so a change fails the simplicity criterion.

## Why each agent missed these

- Rows 1 and 5: the builder tested the paths it ran by hand, not a wrong input or a dropped argument.
- Rows 2 and 3: the term rule was judged on one batch of names and one batch of MCM hints. The lens measured it over the whole reference and 49 batches.
- Rows 9 to 11 and 20: the re-draft was a scratch script, and only the builder had tests. Both copied a shortcut of the importer's rule; Lens 5 traced one id from the importer to the reference and saw the tier. The builder's base check was a third copy, and only a second reviewer ran it with a wrong base.
- Rows 18 and 22: each check was scoped to what the step meant to change, not to every row the step could change.
