# RCA: Story Missions Slice 1, the tier 1 review (2026-11-10)

**Top line:** the tier 1 review of Story Missions Slice 1 (#1105) found one HIGH and one MEDIUM, and both had the same cause: the slice copied two sibling modes and dropped what they refuse. The view list kept neither the Long Defeat HUD's Photo Mode veto nor Host Review's Photo Mode view, so one click on Photo Mode paused the mission for good. The dev menu copied Host Review's mission host but not its block list, so `taom.story_open` opened the mission over an encounter, a town or camp menu, or while enlisted. That broke the slice's one promise, that a story mission writes nothing to the campaign. This is the second time the Photo Mode miss shipped to a review (the Long Defeat Phase 1 RCA, row 1), so the preventive action is a gate, not a note. The first wave ran lenses 5 and 2 and a Step 2c sweep of the behaviors that join every mission; the HIGH started a second wave of lenses 1, 3, 4 and 6 on the view list. A re-review of the fixes found one more MEDIUM: the fix for row 4 wrote a false engine order into a comment (row 11). Codex did not run: the maintainer asked for a quick commit of a feature branch, and the pass is owed before a merge to trunk. Nothing here has run in game.

## Root-cause pattern

Rows 1 and 2 are one pattern, and row 3 is its cousin. A new mode reused a sibling's parts and carried over what those parts do, but not what they refuse or assume. A refusal does nothing visible: an `IsPhotoModeAllowed` override and a `GetBlock` call are both invisible in a list of what a class does. The lesson said so after the Long Defeat Phase 1, and it did not prevent the repeat, because a lesson only helps when it loads and when someone runs its grep. A gate runs every time.

## Why each agent missed these

- **The build's own review** read the new files for defects in what they do, and found four. It did not compare the view list or the menu entry with the precedents' refusals.
- **Lens 5 (data flow)** found row 2 and rows 3 to 8. Row 1 is in a view list, which carries no data flow.
- **The Step 2c sweep** found row 2. Its scope was the behaviors that join every mission, and the Photo Mode view is not one of them.
- **Lens 2 (engine compatibility)** found rows 1 and 2.
- **The orchestrator** wrote row 11 into the fix. It took lens 5's engine premise without a read of the source, which is the failure `evidence-over-claims.md` A.1 names. The re-review of the fixes found rows 11 to 13.
