## What the change does

- `Main/Features/LongDefeat/Domain/RunDifficulty.cs` (new): `enum RunDifficulty { Normal, Hard }`, `RunDifficulties.Id` and `TryParse`, `record HardRules(float Factor, int AffixWavesEarlier)` with `Default = (1.25, 2)`. `RunOptions.Difficulty` defaults to Normal.
- `Main/_Module/ModuleData/long_defeat/waves.json` gains `rules.hard`; `WavesReader.ReadHard` reads it (factor 1.0 to 2.0, earlier 0 to 10) into `WavesConfig.Hard`.
- `LongDefeatConfigCatalog.BuildPlan` applies the difficulty once: on Hard the plan carries `fortress.Waves.Harder(factor)` and `AffixesFor(culture).Earlier(affixWavesEarlier)`. `WavePlan.Harder` scales every wave count (one rounding, half away from zero, after the normal cap, at most 1000) and the endless health and damage growth per wave; `AffixPlan.Earlier` moves each schedule stage sooner, no earlier than wave 1.
- The menu prompt (`LongDefeatSetupPrompt`) asks the fortress, then the difficulty, then the class. `taom.ld_start` takes a last word `normal` or `hard`. The unattended plan (`Autorun/LongDefeatAutorunPlan.cs`) takes an arm key `difficulty`.
- The run report gains `"difficulty"`. The best run is stored per fortress and difficulty (`LongDefeatBestRunStore.KeyFor`: normal keeps the bare fortress id, hard adds `:hard`).
- The co-op session payload (`Coop/LongDefeatSessionPayload.cs`) goes to version 2 and carries the difficulty byte.
- The Python wrapper and judge `tools/run_long_defeat.py`: `--difficulty`, the arm pair, a replay of wave counts and factors (`wave_spec`, `wave_problem`), the shifted affix schedule in `affix_problem`. Tests in `tools/tests/test_run_long_defeat.py`.
- `tools/ingame_checks/1079.toml` and three docs.

Design: `docs/features/long-defeat/phase5-plan.md` (decision D64 and the "State on 2026-11-22" table) and the Difficulty section of `docs/features/long-defeat.md`. The rule that matters most: a NORMAL run must play exactly as it did before this change (the same calls, gold, rolls and report, except the one new report field).
