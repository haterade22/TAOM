# RCA — Dale culture review (2026-05-26)

Issue: [#226](https://github.com/haterade22/TAOM/issues/226) — Dale armor + 27-troop tree.
Review: `docs/reviews/codex-adversarial-dale-2026-05-26.md`. Codex returned 3 findings (P1/P2/P3) after 5 Claude `/deep-review` agents had already passed.

## Top-line

Three confirmed bugs. None blocked shipping; all fixed in-session. The most expensive lesson is **Finding 1**: when overriding a vanilla culture via XSLT, you must enumerate every `CultureObject` deserialize attribute the engine reads, not just the ones the design explicitly cares about. The vanilla XML's passthrough silently preserves bindings you didn't intend to keep.

## Why each /deep-review agent missed Finding 1

The 5 Claude agents passed this work earlier today. None caught the missing 6 XSLT bindings. Reasons:

- **Standards agent** — out of scope; it checks adapter pattern / IoC / region directives etc., not culture-attribute coverage.
- **API Compatibility agent** — verified the 9 attributes that WERE set (basic_troop / elite_basic_troop / 4 militia / default_party_template / 2 equipment rosters) against vanilla `CultureObject.Deserialize`. **Did not enumerate which OTHER attributes the deserializer reads.** This is the scope gap. The agent prompt said "verify the 9 attributes I'm setting"; it should have said "verify the 9 attributes I'm setting AND list every other attribute the deserializer reads that this culture might want to override."
- **Efficiency agent** — not its scope.
- **Completeness agent** — checked the 9 XSLT-bound IDs resolve in their target files (yes, they do). But "every ID I set resolves" ≠ "every ID I need to set is actually set." Asymmetric coverage.
- **Data Flow agent** — traced data FROM the 9 set attributes outward. Did not trace BACKWARD from "what attributes does CultureObject read" toward "which ones are we leaving on vanilla."

The root cause across these agents is **positive-bias review**: every agent checked that what we DID is correct, none checked that what we DIDN'T DO is intentional. This is the same pattern as the dead-toggle / dead-DTO checks already codified in deep-review Standards Agent rule 2b and 2c — extending it to culture-attribute coverage is the natural generalization.

> **Correction, 2026-08-12. Three PASSTHROUGH verdicts in the table above are wrong and were acted on
> as guidance for over two months.** The table is left as written because it is the historical record
> of what this RCA concluded; do not follow rows 55, 58 and 59.
>
> `villager_party_template` was marked "fine for Dale". It was not: Dale's village trade parties were
> vanilla Sturgians, and no `villager_dale_template` existed to bind even if someone had tried. Both
> caravan child rows were marked "not Dale-specific", which reads as a judgement about Dale and is
> really a judgement about all six retagged cultures, every one of which was shipping Calradian
> caravans. `caravan_template_dale` and `elite_caravan_template_dale` did not exist either. All three
> templates were authored on 2026-08-12 and all three bindings now exist.
>
> The two genuinely correct PASSTHROUGH rows are `fishing_party_template` and
> `settlement_patrol_template_coastal` (NavalDLC-only, and unreachable because no TAOM settlement
> declares a `port_posX` pair) and `bandit_boss_party_template` (bandit cultures only).
>
> The deeper lesson is about the form of the verdict, not the three values. "Fine for Dale" and "not
> Dale-specific" are assertions with no evidence attached, sitting in a table whose other rows cite a
> decompiled deserializer. A PASSTHROUGH verdict means "I have checked what vanilla supplies here and
> I want it", so it needs the vanilla value named and a reason. Rows 55, 58 and 59 named a value that
> in two cases did not exist under that name. See
> [`docs/reviews/lessons/xslt-moduledata.md`](lessons/xslt-moduledata.md) FOURTH INSTANCE and the
> binding contract in [`culture-playability-wiring.md`](../features/culture-playability-wiring.md).

## Preventive rule (deep-review Compatibility agent prompt extension)

The deep-review skill's Agent 2 (Bannerlord API Compatibility) prompt currently says "verify each attribute USED has matching signature." It should also say:

> For XSLT overrides on `<Culture id="..."/>`: enumerate every attribute the v1.4.5 `CultureObject.Deserialize` reads, and for each unset attribute, identify which vanilla value passthrough preserves. Flag any case where a TAOM-authored target (party template, equipment roster, troop id) was declared but not bound, leaving the vanilla value to flow through.

This is the generalization of the existing dead-toggle (Agent 5 rule 2b) and dead-DTO (Agent 5 rule 2c) checks, applied to culture-attribute coverage.

## What I learned (process-level)

When the deep-review reports all 5 agents PASS but Codex still finds 3 bugs in a "data-heavy, code-light" change (Dale = ~95% XML), the agents' file-level checks aren't asking the right systemic question. The new XML file looked correct in isolation. What was wrong was the *relationship* between the new file and the vanilla file it overrides — specifically, what the XSLT does NOT touch. Generalising: data-heavy changes need a "what's missing" pass, not just a "what's there" pass. The 5-agent deep-review is largely structured around "what's there is correct" checks; Codex's strength was asking "what's missing relative to the engine contract."

The 1.4.5 `CultureObject.Deserialize` decompilation Codex did is the right level of evidence. Future TAOM culture work should include that decompile as a mandatory Phase 0 step before authoring the XSLT.
