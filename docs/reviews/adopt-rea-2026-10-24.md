## What rea is

A local reverse-engineering CLI and MCP server with one shared workflow layer over providers
(Ghidra, IDA, Hopper, JADX, Frida, mitmproxy and more), for native binaries, Android, JavaScript,
.NET and firmware. Its documentation is strict about evidence: observations, derivations,
inferences and unknowns are kept apart, and an empty result proves absence only inside what was
searched.

## The matcher (#997)

The `architect` designed it from rea's documented method and three read-only probes. The
`implementer` built it test-first. A second `architect` reviewed it adversarially, and the main
session re-ran every number below.

Two design findings came from the probes. First, the engine renumbers method ids between builds
(165 changed from v1.5.4 to v1.5.5), so the oracle keys methods by name; keyed by id, it reported
70 false wrong matches. Second, 942 of the 2,060 single-owner engine-method addresses are leaf
functions with no `.pdata` entry, so the tool indexes leaves cut at the padding.

| Pair | Correct | Wrong | Ambiguous | Unknown |
|---|---|---|---|---|
| v1.5.4 to v1.5.5 | 1,802 (hash 1,797, strings 5) | 0 | 253 | 5 |
| v1.5.3 to v1.5.4 | 1,803 (hash 1,798, strings 5) | 0 | 253 | 4 |
| v1.5.5 client to v1.5.5 wEditor (negative control) | 152 (hash 149, strings 3) | 0 | 428 | 1,481 |

**The review's HIGH finding.** The first version reported zero wrong on both successor pairs, but
those pairs differ by a handful of units. The reviewer ran the client against the wEditor build,
a separate compile, and got 15 wrong matches, 14 of them by unique hash (reproduced by the main
session). Masking was not the cause. A class had gained a member, so field offsets shifted by
0x10 and a neighbour's new code became byte-identical to the old function. The fix is a shift
check: a match stays `MATCHED` only when 2 of the 2 nearest matched units on each side moved by
the same amount. A one-neighbour check left 2 wrong, because two adjacent wrong matches vouched
for each other. With the check, the control gives zero wrong, and neither successor pair lost a
correct match. The control is now part of the integration test.

**The other findings, all fixed:**
- Strings uniqueness was counted only among leftover units. It is now counted over all units.
  Requiring two strings was measured and rejected, because it lost 2 correct matches per pair.
- Three mutants survived the unit tests: an internal branch masked as external, a dropped
  index-register condition, and oracle strings scoring. Each now fails a test.
- A truncated PE ended in a traceback with exit 1. It now exits 2.
- `.text` bounds used the raw size. They now use `min(VirtualSize, SizeOfRawData)`.
- Oracle strings scoring accepted any address inside the unit. It now needs the exact start.
- Dead code was removed and a misnamed constant renamed.
- Both skills run `--oracle` before a carry and read the carried address before using it (on the 1.4.x line, once the plan 137 skill edits land).

The oracle covers thin engine-method wrappers only. On deep code, the v1.5.4 skeleton-pool spins
at `0x69DA4` and `0x6AFD7` carried to `0x6A264` and `0x6B497`, and both v1.5.5 addresses hold the
same three-instruction spin. With zero wrong matches, the gate passed, so the tool is wired into
`/engine-bump` (Phase 1 items 2 and 4, Phase 4 item 7) and `/native-crash-triage` Phase 1 steps 2 and 7 (the same qualifier).
