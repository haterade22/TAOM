## Known suspects (check each)

1. Reverse P/Invoke delegate lifetime and calling convention for the MessageBoxA hook; an exception or a GC of the delegate inside a native callback.
2. Threading: MessageBoxA may be called from any engine thread; `_original` lazy init, `_actionCodeCount` caching, LogRepeatLimiter and DiagLog locks; re-entrancy if DiagLog itself triggers an assert.
3. Is the IAT walk right for PE32+ (offsets 0x3C, optional header + 112 + 8, descriptor fields 0/12/16, 8-byte thunks, ordinal bit)? Could it read out of bounds on a different image?
4. The editor gate `IncompatibleModDetector.IsEditorBin(typeof(Dinen).Assembly.Location)`: can it be true in the game client, or false in the Kit? Shadow copies, an empty Location?
5. Muting `Debug.Assert`/`FailedAssert` while other TAOM code or PatchShield also patches them; prefix parameter names must match the targets (Harmony binds by name).
6. `GetActionCodeWithName` returning -1 early: `ActionIndexCache` bakes -1 permanently when touched before action codes load (docs/reviews/lessons/animation-skeleton.md). Does the guard make anything worse than the native call it replaces?
7. Does any part run on the dedicated server or game client by mistake? Does the SubModule constructor order (before GameVersionNotice) matter?
8. Answer table: any caption or style where an answer is unsafe (Abort, Retry), or a style value outside 0..6.
