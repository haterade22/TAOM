# rtk adoption review (2026-10-23)

Review of [rtk-ai/rtk](https://github.com/rtk-ai/rtk) (Rust Token Killer) against TAOM's AI
harness, through `/adopt-external`. Mike asked how TAOM could use it, showed a `rtk gain` screen
from yotthani (one `rtk grep`, 1.0K tokens in, 309 out, 69.2% saved, 26 ms), and asked for its
effectiveness and efficiency to be measured. He approved the plan on 2026-10-23, including an
offline measured trial of the binary. Issue [#985](https://github.com/haterade22/TAOM/issues/985).

## Coverage

- **Repository:** branch `develop` at `32b2ec4` (838 files), release v1.0.1 (2026-10-14). Read
  through `gh api` and a shallow clone in the session scratchpad; nothing in the clone was run.
  Read at source: `src/hooks/init/claude.rs`, `src/hooks/session_start.rs`,
  `src/hooks/permissions.rs`, `src/core/telemetry.rs`, `src/core/pipeline_remote.rs`,
  `src/hooks/trust.rs`, `engine/src/process.rs`, `install.sh`, `src/cmds/system/pipe_cmd.rs` and
  the `Pipe` command in `src/lib.rs`. A read-only agent covered the hook output, the .NET filters,
  tee and recall, the filter format, `discover` and the git filters, and the main session
  spot-checked its load-bearing claims.
- **TAOM:** the hooks in `.claude/settings.json`, `_shellwords.py`, `tools/harness_retro.py`, and
  the tool output of every local transcript.

## What rtk is

A single Rust binary. `rtk init -g` registers a PreToolUse hook on the Bash tool that rewrites a
known command (`git status` to `rtk git status`), and the binary runs the real command and prints a
shorter version: noise stripped, items grouped, lists capped, repeats counted. Savings are estimated
as bytes divided by 4. The CLI is Apache-2.0; the `engine/` and `proxy/` folders are BUSL-1.1. An
optional proxy daemon (`rtk claude`) routes all API traffic through a local process.

## Security

- **Safe to learn from:** yes.
- **Safe to install into the harness:** no.
  - `rtk init` adds `@RTK.md` to CLAUDE.md, writes RTK.md and patches settings.json
    (`src/hooks/init/claude.rs`). TAOM guards all three.
  - The hook decides permissions itself. `src/hooks/permissions.rs` re-implements Claude Code's
    allow, ask and deny matching and returns `allow` when its own matcher finds an allow rule. Its
    comments name two earlier auto-allow bypasses (#1213 and #1155).
  - Telemetry needs a URL compiled into the build, `consent_given`, and `enabled`;
    `RTK_TELEMETRY_DISABLED=1` turns it off. The payload is a device hash, the version, the OS,
    command names and counts, never command or file content.
  - `install.sh` checks SHA-256 against the release `checksums.txt` and refuses on a mismatch.
    Project filters load only after `rtk trust` records their hash. The engine's `process` step
    runs only binaries named in the source. The SessionStart hook only serves the optional proxy.
- **Automated vet:** `python tools/audit_claude_config.py --root <clone> --external` scanned all
  838 files: CRITICAL 5, HIGH 155, MED 18. The five CRITICAL rows are placeholder keys (an example
  in `SECURITY.md`, `AAAA` test keys in `proxy/src/pipeline/redact.rs`, a test token, a benchmark
  fixture). Of the HIGH rows, 98 are `rm -rf` strings inside permission tests, 12 are the README
  `curl | sh` install line, 15 are network calls in a test script and the installer's version
  check, and 5 are PATH lines in the install docs or test fixtures. None is a runtime path.

## Measurements

### Where TAOM's tool output goes

All 3,427 local transcripts (main sessions and subagents), each result counted once, hold 304,027
tool results with 919.4 M characters. The Read tool returns 47.1% of them, Bash 46.6%, Grep 4.5% and
PowerShell under 1%.
The largest shell families are grep (9.5% of all output), sed, git diff (5.8%) and cat. `dotnet
test` is about 0.2%, with a mean of about 1,000 characters, because sessions already filter it.
rtk's hook sees only Bash, so it can never reach the largest consumer.

### rtk, offline on TAOM's stored outputs

The v1.0.1 Windows release (SHA-256 checked against `checksums.txt`) ran only as
`rtk pipe -f <filter>` and `rtk --version`, with telemetry disabled by its environment variable,
from an empty folder, never on PATH and never initialised. `git status --porcelain` of the main
checkout was identical before and after. rtk wrote one 0-byte marker (`.hook_warn_last`) under
`%LOCALAPPDATA%\rtk`; that folder and the binary were deleted afterwards. Samples were drawn with a
fixed seed; savings are character-weighted with bootstrap 95% intervals.

| Family | n | Saving | Share of all output | Projected | Kept |
|---|---|---|---|---|---|
| Bash grep | 200 | 13.3% (8.7 to 19.3) | 9.50% | 1.26% | 93.5% of match records |
| Grep tool | 200 | 11.4% (5.7 to 17.6) | 4.16% | 0.47% | 96.0% of match records |
| git diff | 200 | 24.9% (20.9 to 28.6) | 5.77% | 1.43% | 80.3% of `+`/`-` lines |
| git status | 200 | 0.2% | 0.65% | 0.00% | 100% |
| find | 200 | 48.5% (42.4 to 53.9) | 0.23% | 0.11% | 54.8% of paths (7.4% verbatim) |

- **Effect on the whole:** 3.3% of all tool-output characters, 2.7% on a cleaner sample of commands
  that were neither piped nor chained. Read holds 47.1%.
- **Cost of the saving:** git diff drops about a fifth of the changed lines, and find keeps about
  ten names per folder. grep keeps ten matches per file (`pipe_cmd.rs` lines 117 to 121); a Windows
  `e:\...:12:` record or a line with no path comes back unchanged, so it neither saves nor loses.
- **Speed:** about 19 ms per call, almost all of it process start.
- **Bias:** offline mode filters the output TAOM already got. The real hook runs its own command,
  for example its own grep with relative paths, and could save more there: yotthani's one `rtk grep`
  saved 69%. Even at 69% on every Bash grep the total stays near 8% of all output, with more
  matches dropped. The Grep tool, Read and PowerShell stay out of reach in every case.

### Which rtk claims held for TAOM

| Claim | For TAOM |
|---|---|
| 60 to 90% fewer tokens | Per command, sometimes (find 49%, one grep 69%). Over a session about 3%, because about half of all output is Read, which rtk never sees |
| Under 10 ms overhead | About 19 ms per call on this machine, mostly process start |
| Native Windows | The binary ran; its grep parser passes Windows-path records through unfiltered |

## The gate fix (#985)

### How it was reviewed

Three `/code-review high` passes and a final medium pass ran on the working tree, each after the
previous fixes, and every finding was reproduced by the main session before it was acted on.

- **Pass 1** found three regressions of the first design, which judged each segment only through a
  quote-aware split: a destructive call inside a quoted `bash -c` script, a commit-message heredoc
  whose `dotnet test` line marked verification, and a heredoc with a redirect after its delimiter
  that hid a later call. A replay of real commands showed the second one at scale: 16 of 17 new
  "plain" marks came from heredoc bodies.
- **Pass 2** found that the blind cut also split at a lone `&` (so it was not the old sed split),
  that `xargs` commits were judged on a `{}` placeholder, and gaps for `bash -lc`, a heredoc with
  text after its delimiter, a closing `)` and abbreviated wrapper options.
- **Pass 3** found a quadratic heredoc scan (a 220 KB command took 30.5 s, past the gates' 30 s
  registration, and a killed gate allows), false marks from heredocs and operands inside `bash -c`,
  and gaps for `env -S`, `env -iC` and `sh.exe`.
- **Pass 4** found that the heredoc pattern widened in pass 2's fixes (text allowed after the
  delimiter) backtracked: a 282 KB command took 42.8 s in `block-dangerous-git.sh`, and the commit
  gates' repository lookup took 44.1 s against 2.2 s at `5c8003b72`; it also read `$((1 << n))`
  as a heredoc and hid a later commit. The pattern went back to its exact text at `5c8003b72`; the
  confirm gates do not need it, because the blind cut catches a call after such a heredoc. Both
  readers inside the hooks got a time bound (20 s in the gates, 3 s in the marker's 5 s
  registration) that falls back to the old split, or to no mark. After the revert the 282 KB
  command takes 1.07 s and still asks.

The rule that settled each fix: a confirm gate never asks less than the old sed split did, because
an extra prompt is the safe direction; the verification marker never marks a mention, because a
false mark silences the Stop reminder. So the gates read the quote-aware segments plus a blind cut
identical to the old `sed` line, and the marker reads only commands a shell runs.

### Accepted limits

| Limit | Why it stays |
|---|---|
| Two Python starts per confirm gate | About 65 to 130 ms on a slow path near 1 s, under 30 s registrations; merging reader modes would add more than it saves ([#661](https://github.com/haterade22/TAOM/issues/661) tracks start-up cost) |
| A multi-line `bash -c '...'` script collapses to its first command | Fails only in the safe direction: the blind cut still sees each git call, and the marker at worst nags once |
| A commit run through `xargs` is not judged by the label gate | Its arguments are built at run time; HEAD does not judge it either |
| A heredoc fed to a shell is not read by the label gate | HEAD does not read it either; the confirm gates and the marker do |
| A heredoc whose delimiter line carries more text (`cat <<'EOF' > f`, `-F - <<'EOF' && ...`) is not stripped | The pattern is HEAD's: the marker can mark a body line there and the label gate cannot read that message, as at HEAD; the confirm gates still see every call through the blind cut |
| Over 64 heredoc openers, or past `REPO_SCAN_MAX`, heredocs are not stripped | Keeps the reader linear; the blind cut still sees every call, and the marker reads nothing past the first opener line |
| `sudo`, `exec`, `eval`, `watch`, `$(...)`, `case` arms, `cmd /c` | Rare in the 10,005 gated transcript commands: no `sudo`, `exec` or `watch` before git, `eval` 3 times, `cmd /c` once. The 60 `$(git ...)` substitutions of a gated subcommand (51 `branch`, 6 `commit`, 3 `stash`) include none with a destructive flag |

### Effectiveness: a replay of real commands

Every Bash and PowerShell command in the 3,427 local transcripts that a git gate or the marker could
judge was extracted (10,005 unique). All 1,530 with a wrapper or grammar form, plus a fixed-seed
sample of 1,500 of the 8,475 others, ran through the hooks at `5c8003b72` and through the final
hooks (3,030 commands, four hooks each). Hooks only parse a command; nothing was executed. A null
control (old hooks on both sides, 40 commands) changed no verdict.

| Hook | Change | Commands | What they are |
|---|---|---|---|
| `block-dangerous-git.sh` | allow to ask | 21 | 18 real calls: 14 `xargs ... git checkout` reverts, and 4 inside loops (`git checkout --ours`, `git checkout --conflict`, `git branch -D`, `git worktree remove --force`). 3 are hook-probe loops whose git text is quoted test data, the accepted cost of the blind cut |
| `block-broad-git-add.sh` | allow to ask | 1 | A real `git add -A` behind a wrapper |
| `check-commit-subject-version.sh` | none | 0 | No sampled command changed; the label gate's gain is the wrapped and grammar forms pinned in `tools/test_hooks.sh` 7e |
| `mark-verification-run.sh` | no mark to mark | 647 | Real `dotnet build` or `dotnet test` runs: 473 behind `timeout` or `time`, 157 in a subshell or loop, 17 after a heredoc whose apostrophes hid them |

No confirm gate asks less than before. A new ask counts as real when the quote-aware reader alone
finds the call; the 3 that only the blind cut finds were read by hand. Every new mark is a real
run, checked by reading the commands, not only by the reader that produced them.

### Efficiency

| Hook | Before, median / p95 ms | After, median / p95 ms |
|---|---|---|
| `block-dangerous-git.sh` | 280 / 404 | 352 / 455 |
| `block-broad-git-add.sh` | 279 / 372 | 345 / 469 |
| `check-commit-subject-version.sh` | 47 / 492 | 47 / 464 |
| `mark-verification-run.sh` | 241 / 349 | 265 / 372 |

A serial pass over 150 fixed-seed commands, old and new interleaved. The two confirm gates pay
about 70 ms for one more Python start; their registrations are 30 s, the marker's 5 s. A 220 KB
command with 20,000 `<<` shifts took 30.5 s in an earlier draft and takes 0.08 s in the final reader. `tools/harness_retro.py`
over the full history took 57 s before section 9 and 72 s after it, for 2.5 M records.

### Section 9 baseline (2026-01-01 to 2026-10-23)

This is `tools/harness_retro.py`'s own count, of records inside its window only, so its total is
smaller than the all-files count above; both put Read and Bash at about half each.
663.9 M characters of tool results: Bash 47.1%, Read 45.9%, Grep 4.8%, PowerShell 0.9%. The
largest shell families: grep 10.2% of all output, sed 9.3%, git diff 6.4%, cat 4.5%, echo 2.5%,
ls 2.5%. `dotnet test` is 0.3%. Any later change that aims to trim output is measured against this
table.

## Decisions

| # | Item | Decision |
|---|---|---|
| A1 | Read each shell segment past wrapper words and shell grammar before judging it | Adopted, as a fix in `_shellwords.py` (#985). rtk's matcher does this; TAOM's gates did not, and the bypass was proven |
| A2 | Measure tool output per tool and per command family from the transcripts (`rtk discover`) | Adopted, as section 9 of `tools/harness_retro.py` |
| X1 | Install rtk or run `rtk init` | Declined: see Security and Measurements |
| X2 | The optional proxy daemon | Declined: routes all API traffic through a third-party local process |
| X3 | rtk's .NET filters | Declined: `dotnet test` is a small share of TAOM's output, and rtk does not rewrite it (#1830) |
| X4 | Tee and `rtk recall` for filtered output | Declined: TAOM already redirects large output to a log and greps it (plans 008 and 010) |
| X5 | The TOML filter format, pipelines and their marketplace, telemetry | Declined: no consumer in TAOM |

Any later idea to trim command output comes back only with section 9 numbers from before and after.
Since 2026-10-24 the retro does this by itself: section 9 compares each run with the previous one
and lists every family that grew by 2 points or more, each row is a proposal candidate, and an
output-trimming change takes its verdict from section 9 ([harness-retro.md](../ai-includes/harness-retro.md)).
