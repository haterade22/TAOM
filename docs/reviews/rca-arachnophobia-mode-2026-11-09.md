# RCA: Arachnophobia Mode (deep-review, 2026-11-09)

## Top-line

`/deep-review` tier 1 ran on the uncommitted #1110 change (worktree `E:/repos/taom-arachnophobia`, base `fc7cd73c4`): Lens 5 (data flow), Lens 2 (engine compatibility) and Lens 7 (XML), plus one Codex pass at `ultra`. No reviewer found a CRITICAL or HIGH defect, so no second wave ran. Four MEDIUM and twelve LOW findings were confirmed against the source and the installed v1.5.6 DLLs, and fixed in the same change. The fix re-review (Codex at `high`, Lens 5) added one MEDIUM and five LOW, all about tests and wording; they are rows 17 to 22. Two proposals were not applied, with reasons below, and one guard question goes to the maintainer.

The two findings that changed behaviour: a spider brood that held regular prisoners could never leave the map, and a leftover spider troop could still upgrade into another spider troop although the setting's hint said no one could.

## Not applied

- **Lens 5 T7, close the routes before the swap.** If a route closer throws, the reorder would skip the swap, and spiders would render. Showing no spider is the feature's first goal; the route the reorder protects leads only to a warg rider. The comment now states this.
- **Lens 2 L2, the Custom Battle fallback** (`CustomBattleService.cs:137-138`) ignores `IsObsolete` and caches per process. It picks only a culture's own basic, elite or militia troop, and only `mirkwood_spiders` names a hidden troop there. Even then the troop rides a warg. Rejected under the simplicity criterion.
- **Codex L1, a per-game outcome key.** The manifest comment and the doc step fix the claim; a key would add state for one test step.

## For the maintainer

- **Lens 2 L4, a guard against an empty upgrade list on a visible troop.** Today no visible troop's only target is hidden: `goblin_lurker` keeps `goblin_sentry`. If future data made one, and that troop were a bandit culture's basic troop, `DefaultAlleyModel` lines 190, 196 and 202 would index `[0]` and throw. The guard (skip the write when the kept list would be empty) or a data test is speculative robustness, so it waits for his word (`simplicity-criterion.md`). Since finding 1, hidden troops can hold an empty list; none of them is a culture's basic troop except the brood husks, which have no edges in XML.
- **Rule line for finding 4.** Proposed for `.claude/rules/tests.md`: "A source pin on a branch names the condition, the call and the exit; before keeping it, name one breaking edit and check that it fails." FOLLOW-UP no issue: a rule edit is the maintainer's call, and the rules review in flight owns that file this month.
