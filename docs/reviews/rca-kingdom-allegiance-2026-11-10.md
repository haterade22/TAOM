# RCA: Kingdom Allegiance (deep-review, 2026-11-10)

## Top-line

`/deep-review` tier 1 ran on the uncommitted #1111 change (trunk `E:/repos/TAOM`, base `3b805cf38`): Lens 5 (data flow), Lens 2 (engine compatibility) and Lens 7 (XML), plus one Codex pass at `ultra`. Bannerlord updated to v1.5.7 (changeset 125802) the same morning, so every engine claim was checked against the installed v1.5.7 DLLs, and the tests ran in a scratch copy (trunk plus the engine bump's compile fix plus this change), because trunk itself does not compile against v1.5.7 (`TaomPartySizeModel`, CS0115, owned by the bump). No reviewer found a CRITICAL or HIGH defect, so no second wave ran. Three MEDIUM and eight LOW findings were confirmed against the source and fixed in the same change; one is a scope question for the maintainer.

The finding that changed behaviour: vanilla's mercenary leave score subtracts the mercenary join score of the clan's own realm, so the veto pushed opposed mercenaries that already serve out of their realm, against the maintainer's "clans that already serve stay", and cancelled itself on a move between two opposed realms. Codex, Lens 2 and Lens 5 each found it.

## Not applied

- **A listener on `OnNewGameCreatedPartialFollowUpEndEvent` instead of the postfix** (Lens 2 F7, information). It avoids a by-name private binding, but the postfix is correct, bound by `HarmonyPatchBindingTests`, and moving it adds a second design for no defect.
- **Checking the switch before the reader runs** (Lens 5 note). It saves two co-op registry probes per score while the switch is off; finding 5 removed the only cost that mattered (log lines). Simplicity criterion: a tiny win for a new seam.
- **Merging the repeated harvest comment pair in `taom_module_strings.xml`** (Lens 7). Tool behaviour, one pair per run.

## Maintainer decision owed

Finding 3: gate the start scenarios (Last Stand, invasions) so they never move an AI clan into an opposed realm, or keep them as a documented limit. They are offered only while War of the Ring is off, and the player picks one once, at new game.

## Why each agent missed what it missed

- **Lens 7** had only the string files; finding 3's effect on the MCM hint was flagged by it as a question for the data-flow lens, correctly.
- **Lens 5** traced every caller of `ChangeKingdomAction`, but the scenarios assign `clan.Kingdom` directly (finding 3). On dead lords it read the listed hero's filter as the page owner's (finding 6).
- **Lens 2** found findings 1, 2 and 6 to 10, but did not census membership paths (finding 3), which was outside its engine-signature brief.
- **Codex** missed the hot-path gate (finding 7) and the dead lords (finding 6); it did not read `config-providers.md`.
- **The implementer** (this session) missed findings 1 to 11: the brief to the reviewers carried the barterable callers as the census, so the self-call in the base model needed an independent census to surface.

## Rules to codify

- **`.claude/rules/gamemodels.md` rule 1** (applied 2026-11-10, in the commit after the fix): before overriding a model method, grep the base model (and the engine) for every call of that method, the base class's own virtual self-calls included, and decide for each reader whether the override must answer it.
- **`.claude/rules/adapters.md`** (repeat of #952; applied in the same commit): a singleton adapter that must hold engine objects between calls of one operation exposes a release the service calls in a `finally`; otherwise it carries the object inside the snapshot.
