**Top line:** the tier 1 `/deep-review` of the field trial harness ran after the harness's first run in the game, because that run was the feature's first in-game proof and the harness shows nothing until it runs. The first wave (lens 5, lens 2, Tooling) found one HIGH: the wrapper exited 0 on a deploy that was not the tree under test. The first run itself stays valid: its stamp sha equalled `HEAD`, no changed file was newer than the build, and re-judging its log gave exit 0. Lens 2 found no incompatible engine call. The HIGH sent a second wave (lens 1, 3, 4, 6, at `effort: "high"`) over the whole harness, after the first wave's fixes. That wave found no HIGH and six MEDIUM, and lens 6's proposals reshaped the script before more stages land on it. One convergence pass found only LOW items. Three game runs bracket the work, and the third ran the reshaped harness.

## Root-cause patterns

**Copying a shape copies its gaps (1, 5, 6, 15).** The contract named sibling runners as the shape, and both lack the build check. A named shape needs a question beside it: what does the shape not do that this job needs? `ingame_verdict.py` and `FordsAutorunOutput` already held the two answers.

**A gate or a test that cannot see what its name says (2, 3, 4, 12, 13, 19, 31 to 36).** Each passed with the behaviour removed. The Tooling lens and the fixer found them by mutation: break the code on purpose, and read which test notices.

**A fix read less closely than new code (23, 28, 29, 39).** Each of these came from an earlier fix in this same review, and each fix looked complete to its author and its checker. A later lens that ran the function, or read the next stage's contract, found the gap.

**Prose that outlived its evidence (15, 16, 18, 20, 21, 22, 37, 40).** Every wrong sentence was true of something nearby: the spike, the epilog, a summary line. The first run changed the facts, and only the reviewers re-read the prose.

- **The harness builder** worked from the contract and its named shapes, so it inherited rows 1, 5 and 15 from them.
- **The harness checker** compared the code with the contract's sentences. The contract held the gap, so the check passed.
- **Tooling** found 1 to 4 and 12 to 17 by driving the real `run_once` with a fake game and 21 mutants. It stopped at the wrapper, and it reported row 5 as a matter for the maintainer, because it could not name a frequency.

- **The first-wave fixer** wrote row 23's gap into its own fix and its own fixture. A fix gets the same reading as new code, and only the next wave gave it that.
- **Lens 3 (Efficiency)** found rows 23 to 26 by running the real `stale_build` on each state, and found no performance issue in the C#. It left one route unverified: `[BuildStamp]` covers `TAOM` and `TAOM.Dependencies`, not `TAOM.Client`.

- **Lens 4 (Completeness)** found rows 31 to 37 by reading, because its role runs no `dotnet`. Its "survives" claims were readings until the fixer's RED step ran them.
- **Lens 6 (Design)** found row 29 and the reshape below. Two of its eight proposals were not applied as written: see "Design proposals".
- **Lens 5 and Tooling** ran in the first wave, before these fixes existed. Tooling's mutants covered the wrapper and not the autostart, so row 27 sat outside what it drove.

## Design proposals (lens 6)

Applied: steps as iterators, with `Verdict.InMissionTick` as the one seam for section 12's tick rule; one file per feature at each shared list; `BrokenWorld` deleted; S1's tests named their own six steps; the host takes the session and the one adapter (row 29); the dead `Advance` branch and `_deploymentFinished` deleted, after quoting the engine lines that change the mode inside the call.

Not applied: reading the wrapper's step list from the C# table, because a table that only partly matches would silently drop a row, and a tuple with its tie test fails loudly. Replacing the porcelain parser with two listings, because `--no-renames` removes the same branch with one flag; the real-git test it asked for was kept.

**Trade-off stated:** the rewrite of six working handlers cost one more game run and about one builder round. It pays back at the next stage, because sections 6 to 11 and Marshal's section 11 add at least 28 more steps to a class that already held eleven shared fields.

**Disagreements:** Tooling marked the status collision for the maintainer's word, and lens 5 said to fix it before commit. Lens 5 named the producer and proved the throw, so the speculative row of the simplicity table no longer applies. Fixed.

## Lessons codified

- `lessons/build-tooling-workflow.md`: an unattended wrapper binds its PASS to the build under test; a heartbeat write never ends a run, and a done write never loses the quit.
- `lessons/testing-qa.md`: quote what a counter counts before you cite it as a clean log; a fix's test helper must not default to the state the fix is about; take a fixture from the first real output; a scan gate reads where the banned write would live.
