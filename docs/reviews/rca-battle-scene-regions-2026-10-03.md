# RCA: battle-scene regions (deep review, 2026-10-03)

## Top-line

The change replaced the Calradia-era `sp_battle_scenes.xml` with a Middle-earth region mapping generated by the new
`tools/build_battle_scenes.py`, re-enabled TAOM's 8 field scenes (Mike accepted the #287 GPU crash risk), and
documented the system. An 8-lens `/deep-review` (Opus 5.5, max effort; wave 1: engine compatibility, data flow,
XML, tooling; wave 2: standards, efficiency, completeness, design) confirmed **2 HIGH, 3 MEDIUM and 6 LOW**
findings. All were fixed before commit except the follow-ups listed at the end. Proof after the fixes:
`python -m unittest tools.tests.test_build_battle_scenes` 25 OK; `python tools/build_battle_scenes.py --check`
exit 0, "up to date"; `python tools/lint_docs.py --fail-on-drift` 0 dead links, 0 new dashes; full `tools/tests`
and `dotnet test TAOM.Tests` each at their pre-existing single failure (career kits; translation rows), neither
touched by this change. Each finding was re-read against the code or the settlement data before it entered this
table.

## Root-cause pattern

Findings 1, 3 and 6 share one cause: **the evidence was measured once, then the artifacts were written from memory
and the picture rather than from the measurement.** The settlement sampling was right (the engine lens later
proved the transform from the native decompile and a logged battle), but the code, the doc table and the numbers
were each typed separately. Findings 2 and 4 share another: **a gate existed as a rule or a name, and the new
tool did not meet it**, because the rule's trigger never fired and the named tool could not fail.

## Why each lens caught what it caught

- **Engine compatibility:** proved the y-flip in native code, corrected two doc facts (index 0, the vanilla list), found the latent empty-`map_indices` crash from `GameSceneDataManager`.
- **Data flow:** the only lens to diff `REGIONS`, the doc table and the settlement dump cell by cell (finding 1, the "(visual)" errors, cells 46, 77, 110, 114), and to prove TAOM's prefix replaces rather than appends vanilla's lists.
- **XML:** the same HIGH from the settlement side, plus the stale precompile comments.
- **Tooling:** reproduced finding 2 against the real `main()` and showed no gate catches it; findings 5 and 9.
- **Completeness, design, standards:** the missing CI check of the committed file (finding 4), the untested branches (8), the stale docs (7), and the shared-file staging risk. Efficiency found no in-game cost.

## Convergence pass

One reviewer checked only the improvements applied after wave 2. Code parity was proven byte for byte (the
pre-improvement generator rebuilt from the edit script, matching on the real table and four edge cases), and every
new test went red when its guard was removed. It found two LOW defects in those additions, both fixed: a test
pinned a refusal of trailing hyphens in region names that cannot break the comment (the clause was deleted; the
parse check still refuses real breakage), and the recipe taught summing the printed scene counts, which
overcounts a scene two regions share (cell 114 holds 12 scenes, not 15). Three nits were fixed with them: `True`
passed as a cell, a misleading loop comment, and a doc claiming `--check` was the only failing check.
