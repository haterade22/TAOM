# RCA: the Chinese team import (#1385)

Findings from the review of #1385 Phase 1: `tools/import_team_translations.py`, its tests and docs, and
the import of the Chinese team's text into TAOM's `CNs` and `CNt` files, the translation caches and the
live TAOM_Map and Armory files. The change writes live TAOM_Map and Armory data, so it ran as tier 1:
the data flow, engine compatibility, XML and tooling lenses at `max`. Codex did not run: it has had no
usage since 2026-11-15, and the maintainer said to skip it. The first wave reported HIGH findings, so a
second wave ran the efficiency, completeness and design lenses at `high`. The first import (24d636cc5)
was pushed to the branch before the first wave reported, with its known defect in the commit body, and
was held from trunk; dbdaf3e87 took it out and fixed the tool, and the import then ran again on the
merged trunk English. Row 3 came from the check of that second import's report. Each row was read again
against the files before it was fixed; row 18 was also read in both language files and both caches.

## Not applied

- Tooling T9: no size cap on zip members. A guard for a speculative case needs the maintainer's word (`simplicity-criterion.md`).
- Tooling T10, data flow trace 11: a third parser of TAOM_Map's inline settlement keys, which decodes four XML entities where the other two decode none. FOLLOW-UP no issue: no keyed default holds an entity today.
- Data flow trace 3: the team re-keys 180 TAOM_Map fields in its XSLT under its own keys, so their text for those fields is in `theirs_only`. This is Phase 2 of #1385.
- Completeness 4: in 140 CNs and 101 CNt `stale` rows our kept text equals the team's, so both translate the old English (`TAOM_clan_sturgia_2` is "Mueller" and reads 巴德家族). The guide now says a kept row can be stale and points to the reset checklist; the reset itself belongs with XML F2 below.
- XML F2: 205 CNs and 242 CNt rows, ours and the team's, translate English that fa6f17d68 and 3cd778a26 changed without resetting any language row. They are in the `stale` list and keep ours, which is also stale. FOLLOW-UP no issue: the reset covers all 12 languages and is the maintainer's to schedule; the id lists are in the review's `blame_CNs.json` and `blame_CNt.json`.
- The team worked from a trunk build later than the v2.0.38 its `SubModule.xml` names (the drop holds Realms title rows that came after that tag). The tool keeps the declared base, so up to 41 good rows per language stay ours. TRANSLATOR_GUIDE asks the team to name the exact build.
- Completeness, merges: `git log --full-history` lists more commits per source (196 against 62 for `taom_module_strings.xml`). The completeness and design lenses each read the extra commits: they add 0 English texts, so the flag would triple the `git show` calls for nothing.
- Efficiency, batching `english_after` into one `git cat-file --batch`: about 2 s saved on a tool run a few times per drop, for a hand-written blob reader (`simplicity-criterion.md`).

## Why each agent missed these

- Rows 1, 3, 4 and 5 needed the git history of our English or the whole list a player picks from. The builder wrote the tool from the drop's language files and checked it row by row.
- Row 3 needed a second import on newer English: the first import's report had 30 new ids and no changed one.
- Row 18 needed every name list screened. The first wave looked at the lists where it saw damage; the design lens simulated the guard on each name file.
