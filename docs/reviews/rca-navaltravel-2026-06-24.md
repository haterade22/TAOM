## Root-cause pattern

Both findings are the same root cause: **incomplete enumeration of how the engine propagates and recomputes naval state across parties and across the enabled/disabled + on-land/at-sea lifecycle.** The capability gate is not a per-party-isolated decision — the engine pushes `IsCurrentlyAtSea` down the attachment tree and recomputes capability per party, so a naive `IsMainParty` gate desyncs armies (HIGH) and a naive `!IsEnabled → vanilla` gate strands mid-voyage parties (MED). The unified fix encodes the correct mental model in one pure method: **already-at-sea ⇒ capable (reach land); else gates govern embark-from-land; else inherit the army leader's capability.**

## Why each deep-review agent missed it

- **Standards / Efficiency / Completeness:** out of scope — these are behavioral/engine-propagation bugs, not standards, perf, or coverage gaps.
- **Compatibility (API):** verified all 21 signatures resolve (they do) — but a correct-signature call can still encode wrong *semantics*; it doesn't trace runtime propagation.
- **Data Flow:** traced config→model and disabled-path, and even reasoned the ungated terrain methods were "harmless because no party has Naval capability when disabled" — which is exactly the assumption that's false for the at-sea transient. It did not open `MobileParty` to see `IsCurrentlyAtSea` propagate to attached parties. **The gap: the data-flow agent traced TAOM-internal flow but not the engine-internal propagation the override feeds into.** This is a known class — "data-flow agent traces TAOM code, not the engine internals the GameModel result flows into."

Net: I anticipated #1 myself (it was Known Suspect #2 in the Codex prompt) and shipped it pending Codex confirmation rather than fixing pre-emptively — acceptable given the review-then-fix loop, but the deep-review agents alone would not have caught either; the independent Codex pass earned its keep here.

## Feedback memories to codify

1. **`feedback_gamemodel_capability_engine_propagation`** (new): overriding a per-party capability GameModel (`PartyNavigationModel.HasNavalNavigationCapability` and kin) requires mirroring the engine's cross-party propagation — `IsCurrentlyAtSea` pushes down the attachment tree and `NavigationCapability` is recomputed per party — or player-led armies desync at sea. Already-at-sea parties must retain capability to reach land. The reference donor (NavalDLC) encoded the attached-to inheritance; preserve it when you swap the gate.
2. **Reinforces `feedback_native_port_hot_path_audit` (generalized):** when you keep N-1 limbs of a faithful port and rewrite limb N, re-audit limb N's *entire* behavior, not just the sub-change you intended. The dropped attached-to inheritance is the managed-code analog of the unaudited hot-path logging.
