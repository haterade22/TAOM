# RCA: 1.5.x port of the PR #1064 campaign fixes (#1068, #750, deep-review, 2026-10-30)

## Top line

Jopila's PR #1064 brought three Bannerlord 1.4.8 fixes to the frozen `bannerlord-1.4.5` branch: the
supply route path query, the supply route arrows' terrain height query, and alignment desertion during a
map event. The outside-PR review found a compile error in the PR (an `out` argument to a `ref`
parameter) and requested changes; the same three defects were then found on `bannerlord-1.5.x` and
ported. `/deep-review` ran at tier 1 (native calls and a campaign tick): lenses 5 (Data flow) and 2
(Engine compatibility) in one wave, Codex at `ultra`, and one convergence pass. No finding was HIGH or
CRITICAL, so no second wave ran. Two MEDIUM and several LOW findings were confirmed and all were fixed
before the commit.

The pattern behind the findings: the port carried the contributor's 1.4.8 crash explanations and test
style across without re-deriving them on 1.5.6. A comment repeated a crash mechanism that the 1.5.6
native code contradicts, and the first tests pinned call order where a behavioural test was reachable.

## Why each review missed what it missed

- **The first implementation pass** wrote the comment from the PR's write-up (finding 3) and chose IL tests because both methods need a live campaign or scene (finding 2), without checking whether part of each could be reached with fakes.
- **Lens 5 (Data flow) and lens 2 (Engine compatibility)** found findings 1, 3 and 5 and flagged that the tests pin call order (lens 2 F4), but did not plant the copy-paste or polarity mutants; their brief asked about bindings and flows, not about test strength. Lens 5 also called the route and ETA "one rule set" while tracing only settlement sources (finding 4).
- **Codex** planted mutants in memory and found finding 2 and finding 4; it found no production defect.
- **The convergence pass** confirmed findings 2 and 4 independently and added 6 and 7.

## Accepted limits

- The arrows' test still cannot see a terrain query moved outside its branch while a branch on the heightmap remains: `Scene` is sealed and native, and the IL fingerprint drops branch targets. The test comment says it pins the shape.
- The no-heightmap fallback reaches a native helper that reads the scene's physics pointer without a null check (convergence pass, UNVERIFIED whether that pointer can be null in the state that drops the heightmap). Vanilla calls the same path routinely (`CampaignVec2.AsVec3`).
- Neither 1.4.8 crash was reproduced on 1.5.6. The in-game checks are owed on #1068 and #750.
