# File catalogue

## What this file is

This chapter lists every file under `ModuleData` in the three modules TAOM's data spans (the repo's `TAOM` module, the live `TAOM_Map` map module and the live `LOTRLOME_Armory` items module) and says, for each one, how it gets loaded, which engine class or C# loader reads it, what it is for, which script writes it, and whether the repo or the game install holds the real copy. It also carries the master table of the JSON and C#-loaded XML configs with their loader, reload scope and MCM precedence, which [configs-balance](configs-balance.md) and [configs-factions-and-world](configs-factions-and-world.md) link to rather than repeat. Every count was measured on 2026-09-05 with the command shown beside it, and where a research note and the disk disagreed the disk won.

## How to read the tables

Four mechanisms load a file, and a file that none of them names is dead data no matter how correct it looks. [Submodule and registration](submodule-and-registration.md) covers each in full and [Load order and dependencies](load-order-and-dependencies.md) covers the order they run in; the short version, with the engine lines:

- **`SubModule.xml` `<XmlName id="..." path="..."/>` rows** are read at launch (`XmlResource.cs:149`). When the engine asks for an id it walks every module's rows for that id in load order (`MBObjectManager.cs:877-917`): if `ModuleData/<path>.xml` exists it is merged; if `ModuleData/<path>/` is a folder, every `*.xml` inside it is merged (`MBObjectManager.cs:901-909`); if neither exists the row still contributes its stylesheet (`MBObjectManager.cs:911-915`). That last branch is how the repo's eight XSLT-only rows and the Armory's two work.
- **`project.mbproj` `<file id="soln_..." name="..."/>` rows** feed the native side (`XmlResource.cs:117`, `MBObjectManager.cs:920-947`). Only `<file>` elements are read, and only for the ids the engine asks for. An invented id, or a row written as `<Module>` instead of `<file>`, loads nothing and logs nothing; the history is in [lotrlome-soln-id-fix](../reference/lotrlome-soln-id-fix.md) and the gate is `python tools/audit_mbproj_registration.py`.
- **XSLT sidecars** are never named anywhere. For a row with `path="x"` the engine probes `ModuleData/x.xsl`, then `ModuleData/x.xslt` (`ModuleHelper.cs:237-240`, `MBObjectManager.cs:949-964`), and applies the stylesheet to the document accumulated from every earlier module before this module's own XML is merged in (`MBObjectManager.cs:966-982`).
- **Hard-coded engine paths.** `ModuleData/Languages/**/language_data.xml` is found by a recursive scan of every loaded module (`LocalizedTextManager.cs:91-99`), and `ModuleData/global_strings.xml` is opened by that literal name in every module (`GameTextManager.cs:134`). Neither needs a `SubModule.xml` row, and a row would not help.
- **C# loaders.** TAOM's own providers under `Main/Features/` build a path with `Path.Combine(ModuleDataPath, ...)` and open the file themselves. Every JSON file and fifteen XML files load this way, and they are invisible to `SubModule.xml` and to `project.mbproj`.

Column vocabulary. **Registered by** names the mechanism and the row (a `SubModule.xml` line number is the `<XmlName>` line). **Reads it** is the engine class the id maps to, with the `RegisterType` line and the `LoadXML` line, or the C# class for a loader. **Tools** lists the `tools/` scripts whose source names the file. The list came from grepping `tools/` for each file name, and every script named here exists on disk, but that grep proves only that the script mentions the file, not that it writes it: `tools/clan_registry.py` builds a read-only registry from `characters/clans.xml` and `spclans.xslt`, and the `analyze_*` scripts read and report. Open the script before running it. "hand" means no script names the file. **Status** is one of `repo` (the repo copy is authoritative and the build deploys it), `live` (exists only in the game install), `stale shadow`, `stub` (a scaffold with no entries), `dead` (nothing loads it) or `build-time` (a script input the game never opens).

The first live path in this chapter is `TAOM_Map/ModuleData/settlements.xml`. This file lives in the game install, not the repo; a module reinstall reverts hand edits, so land a repo-side validator gate with any fix. The same sentence applies to every `TAOM_Map/` and `LOTRLOME_Armory/` path below.

## Config master table: 64 JSON and 15 C#-loaded XML

Two rules govern every row here.

**Reload scope.** Every config provider is registered `Reuse.Singleton`: 42 `ConfigProvider` registrations across `Main/Features/*IoC.cs`, all singleton, and none of the provider classes has a reload method. <!-- measured: grep -rhn --include='*.cs' "ConfigProvider>(" Main/ then grep Register, 42 lines, 41 of them carrying Reuse.Singleton on the matched line and the 42nd (FieldCommissionIoC.cs:38-40, a RegisterDelegate) carrying it on line 40; grep -rln --include='*ConfigProvider.cs' "Reload" Main/Features returns nothing, 2026-09-05 --> A singleton caches for the whole Bannerlord process, so an edit to any of these files needs a full game restart, not a new campaign and not a save load ([csharp-architecture rule, line 94](../../.claude/rules/csharp-architecture.md)).
