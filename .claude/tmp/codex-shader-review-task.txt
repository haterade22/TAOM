## Feature Description
ShaderPrecompilation adds a main menu button that launches a custom battle with all TAOM troops to force the Bannerlord engine to compile and cache shader permutations. Recent changes: added confirmation dialog, increased troop cap from 500 to 2000 per side with soldier x4 multiplier, removed bandit filter, added background shader monitoring in OnApplicationTick.

## KNOWN SUSPECTS

1. TROOP CAP OVERFLOW: With SoldierCopies=4 and MaxTroopsPerSide=2000, if there are many soldiers, the last characters in the list may be silently dropped because copies won't fit in either side. CONFIRM whether characters are silently lost and whether this matters for shader coverage. Check: can both sides fill up leaving characters unprocessed?

2. EARLY RETURN IN TICK: OnApplicationTick has `if (_shaderTickAccumulator < 1f) return;` which exits the entire method. The _timeAccelerationService?.OnTick() runs before this check, so it always executes. But if any future code is added after the shader block, the early return would skip it. CONFIRM or DISPUTE whether this is a real risk or acceptable.

3. DIALOG CLOSURE RACE: The cancel action calls InformationManager.HideInquiry(). The confirm action calls MBGameManager.StartNewGame(). CONFIRM whether both can fire, or whether the dialog prevents double-click.

4. STATIC STATE LIFETIME: _shaderTickAccumulator and _lastShaderCount are static fields in SubModule. They survive module reload. CONFIRM whether stale values from a previous session could cause the first shader compilation message to be suppressed (if _lastShaderCount happens to match the new count).

5. HASHSET TO LIST CONVERSION: GetCultureIdsForShaderBattle() calls GetValidCultureIds().ToList(). HashSet does not implement IReadOnlyList. CONFIRM the .ToList() is necessary or whether there is a better return type.
